## 2. 测试设计

### 2.1 工程化约定
- 测试依赖统一声明于 `requirements-dev.txt`（`-r requirements.txt` + `pytest>=8.0` + `httpx>=0.27`）。
- `pytest.ini` 配置 `testpaths = tests`、`pythonpath = .`。
- 复用 `app` 既有的统一响应结构 `ApiResponse{code, message, data, trace_id}` 与业务码（0 成功；40000 业务错误、42200 参数校验、40300 禁止、40400 不存在、40100 未认证）。

### 2.2 关键 Fixtures（`tests/conftest.py`）
| Fixture | 作用域 | 说明 |
| --- | --- | --- |
| `client` | session | `TestClient(app)`，真实启动应用 |
| `admin_headers` | session | L0 管理员 Bearer Token，登录前复位 admin 失败计数 |
| `test_space` | session | 创建 `functest_` 空间；teardown 删除角色+空间记录+`DROP DATABASE mig_functest_*`（硬删，可重复执行） |
| `member_headers` | session | 创建 L2 成员并绑定到测试空间（teardown 硬删用户） |
| `outsider_headers` | session | 无空间角色用户（teardown 硬删用户） |
| `throwaway_user` | function | 破坏性场景用的一次性用户 |
| `captcha_helper` | — | 领取验证码并直接解码，绕过图形校验 |

辅助断言：`assert_ok`（HTTP 200 + code==0）、`assert_biz_error`（HTTP 200 + 指定业务码 + 可选关键字）；文件工具：`xlsx_upload`/`csv_upload`/`read_xlsx`/`uid`。

## 5. 修复记录（测试代码问题，非产品缺陷）

验证过程中发现的失败**均源于测试用例本身对实现的假设偏差**，已修正，后端业务逻辑未发现缺陷：

| 序号 | 用例 | 问题 | 根因 | 修正 |
| --- | --- | --- | --- | --- |
| 1 | `test_account_lockout_after_threshold` | 期望「第 10 次失败」立即返回 40300「已锁定」 | `auth._register_failure` 在计数达阈值时设置 `locked_until` 并重置 `login_fail_count=0`，**本次响应仍为「还可尝试 N 次」(40000)**，锁定在**下一次登录**（`auth.py:59`）才强制拒绝 | 改为先触发一次失败（count 9→10 锁定），再用**第二次**登录断言 40300；并补充「锁定期间即便密码正确也被拒绝」断言 |
| 2 | `test_create_space_invalid_code` | `"Abc"` 返回 40000「项目简称已存在」而非预期的 42200 | 后端对 `space_code` 执行 `strip().lower()`（`space.py:76`、`schemas/space.py:26`），`"Abc"` 归一为合法 `"abc"`，与历史残留记录撞重名 | 从非法清单移除 `"Abc"`；保留真正正则/长度非法的 `"1abc"`/`"a"`/`"a-1"`/`"中文项目"` |
| 3 | `test_export_and_template` | 空场景导出仅表头、行数断言失败 | 用例未先插入库表数据即断言导出内容 | 在导出前先插入 2 条库表（`ods.表`） |
| 4 | `test_import_tasks_overwrite_and_incremental` | `task_uri` 断言用场景名而非空间名 | `task_uri` 由**空间名**派生（`空间名://任务@工作流`），用例误用 `scenario["name"]` | 改用 fixture 暴露的 `scenario["space_name"]` |

> 补充：历史运行曾因中断在开发库残留 `mig_abc_db` 及 `abc`/`functest_*` 空间记录，已在收尾阶段统一清理（`DELETE` 空间记录 + `DROP DATABASE` + 删除 `functest_` 测试用户），并核对线上开发库仅保留 `admin` 与预置 `test` 账号。

## 6. 复现方式

```bash
cd code/backend
# 安装测试依赖（首次）
.venv/bin/pip install -r requirements-dev.txt

# 运行（需可连通 MySQL；DB_TYPE 与 MYSQL_URL 指向开发库）
MYSQL_URL="mysql+pymysql://<user>:<pwd>@127.0.0.1:3306/mig_common_db" \
DB_TYPE=mysql \
.venv/bin/python -m pytest -q
```

测试套件自带清理，可安全重复执行；如担心残留，可在运行后检查 `mig_common_db.b01_space` 无 `functest_%` 记录、且无 `mig_functest_*`/`mig_abc_*` 数据库。
