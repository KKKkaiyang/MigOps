## 1. 概述

### 1.1 背景与目标
在既有用户权限与项目空间管理基座（见配套文档）上线后，结合实际操作诉求，对以下三类体验与能力进行优化：

1. **用户中心自助改密**：当前用户改密仅能通过「管理员重置 → 临时密码强制改密」流程触发（配套文档 §4.3）。需在登录后的用户头像下拉框中，为**任意登录用户**提供自助「修改密码」入口，提升自助性与安全性。
2. **项目空间管理列表「进入项目」入口**：当前空间管理列表（`/b01/spaces`）仅提供成员 / 编辑 / 状态操作，缺少直达空间工作台的入口；需补充与首页 Panel 区一致的「进入项目」能力。
3. **系统管理员物理删除项目空间**：需支持 L0 系统管理员在管理列表中**物理删除**某个项目——删除后后端对应的空间数据库实例（`mig_<space_code>_db`）被直接 DROP，实现数据不可逆清理。

### 1.2 范围
- **涉及前端**：应用头部用户下拉（`App.vue`）、项目空间管理列表（`SpaceList.vue`）。
- **涉及后端**：复用已有 `POST /common/auth/change-password`；新增 `DELETE /b01/spaces/{space_id}`。
- **涉及库**：空间业务库 `mig_<space_code>_db`（物理删除目标）；公共库 `mig_common_db`（保留空间元数据，见 §4.3）。

### 1.3 术语
| 术语 | 含义 |
| --- | --- |
| 物理删除空间 | 直接 `DROP DATABASE` 删除空间业务库，库内全部业务数据不可恢复 |
| 元数据保留 | 公共库中 `b01_space` 主记录与 `common_user_role` 绑定逻辑保留（置删除标记），用于审计追溯 |
| 强确认 | 需用户手动输入空间名称/编码方可执行的二次确认机制 |

## 3. UR-01 用户中心：头像下拉「修改密码」

### 3.1 功能描述
登录后，应用头部右侧用户头像 / 名称区域的下拉菜单中，在「退出登录」上方新增「修改密码」菜单项。点击后弹出改密对话框，用户完成自助改密。

### 3.2 交互与界面
- **入口位置**：`App.vue` 头部用户下拉菜单（现有项：用户名（禁用）、退出登录），新增「修改密码」项，建议与「退出登录」之间以分割线区隔。
- **对话框字段**：
  - 原密码（必填，输入框 `type=password`）
  - 新密码（必填，满足 §6.1 复杂度）
  - 确认新密码（必填，须与新密码一致）
- **校验**：
  - 前端：新密码复杂度提示、两次输入一致性；任一不通过则禁用「确定」。
  - 后端：复用 `POST /common/auth/change-password`，校验原密码正确性与新密码复杂度（配套文档 §7.1）。
- **结果反馈**：
  - 成功：`ElMessage.success("密码修改成功")`，关闭弹窗，**当前登录会话保持不变**（JWT 与密码无关，令牌继续有效）。
  - 失败：后端返回业务错误（如「原密码错误」「新密码不满足复杂度」），由请求拦截器统一提示，弹窗不关闭，便于重试。

### 3.3 权限与可用性
- **适用角色**：所有已登录用户（L0 / L1 / L2）均可自助修改**本人**密码；不涉及他人账号。
- **与强制改密的关系**：现有「临时密码登录 → 强制改密」流程（`Login.vue`）继续保留；本条为**主动自愿改密**入口。建议抽取共用改密组件（`ChangePasswordDialog.vue`）：
  - 自愿改密模式：用户需手动输入原密码，弹窗可关闭。
  - 强制改密模式：原密码由登录态注入、对用户输入隐藏，弹窗不可关闭（`close-on-click-modal=false`、`show-close=false`），改密后方可继续。

### 3.4 后端接口
复用既有接口，无需新增：

```
POST /api/v1/common/auth/change-password
请求：{ "old_password": "...", "new_password": "..." }
响应：{ "code": 0, "message": "ok", "data": null }
```

## 4. SP-01 项目空间管理列表：「进入项目」入口

### 4.1 功能描述
在项目空间管理列表（`/b01/spaces`）每行的操作区，新增「进入项目」按钮，点击后跳转至该空间的工作台视图（`/space/{space_id}`），与首页 Panel 区的「进入空间」行为保持一致。

### 4.2 交互与界面
- **入口位置**：`SpaceList.vue` 操作列（现有：成员 / 编辑 / 状态），新增「进入项目」按钮（`type=primary` 链接样式，置于操作区最前或靠前位置）。
- **跳转行为**：`router.push(\`/space/${row.id}\`)` → 进入 `SpaceLayout` 框架（空间头部 + 模块导航 + 子页面）。
- **可见性**：列表本身已按权限过滤（L0 看全部、L1/L2 看所属空间），故对列表中出现的每一行均显示「进入项目」。

### 4.3 权限说明
- L0 / L1 / L2：凡在列表中可见的空间，均可进入（与既有空间访问控制一致）。
- 与后端空间内接口鉴权（`require_space_member` 等）解耦——前端仅负责跳转，真实数据访问仍由后端逐接口鉴权兜底。

## 5. SP-02 系统管理员物理删除项目空间

### 5.1 功能描述
L0 系统管理员在项目空间管理列表中，可对任一项目空间执行物理删除：删除后后端直接 `DROP DATABASE` 该空间的业务库，实现不可逆清理；公共库中的空间元数据保留以便审计。

> 本需求**有意偏离**全平台默认的「逻辑删除」约定（见 `CODEBUDDY.md` §3.3 `deleted_at` 规范）——空间业务库被物理销毁，但公共库元数据采用逻辑标记保留，属经确认的特例。

### 5.2 权限控制（已确认）
- **仅 L0 系统管理员**可在管理列表看到并执行「删除」操作；L1 / L2 不显示该按钮。
- 后端接口以 `require_l0` 强制拦截，非 L0 调用返回 `40300 Forbidden`。

### 5.3 强确认机制（已确认）
物理删除属高危不可逆操作，**必须**采用「输入空间名强确认」：
1. 点击「删除」→ 弹出危险样式确认对话框。
2. 对话框展示待删空间的：**空间名称、空间编码、绑定数据库名**，以及醒目危险警告文案（如「此操作将永久删除数据库 `mig_xxx_db`，库内全部业务数据不可恢复」）。
3. 对话框内提供输入框，用户须**手动输入该空间的名称（或编码）**，仅当输入与待删空间完全一致时，「确认删除」按钮方可点击（否则禁用）。
4. 点击「确认删除」→ 调用后端删除接口。
5. 成功：`ElMessage.success`，列表刷新（该空间不再出现于活跃列表）；失败：拦截器统一提示，弹窗保持。

### 5.4 删除范围（已确认）
| 对象 | 处理方式 |
| --- | --- |
| 空间业务库 `mig_<space_code>_db` | **物理删除**：`DROP DATABASE IF EXISTS \`mig_<space_code>_db\`` |
| 公共库 `b01_space` 主记录 | **保留**，置逻辑删除标记：`deleted_at = now`、并将 `status` 置为终态归档值（如「已删除」），使其从活跃列表过滤掉 |
| 公共库 `common_user_role` 成员角色绑定 | **保留**（按需求「仅删库保留元数据」）；因空间已逻辑删除，其成员关系不再参与活跃鉴权 |
| 后端空间引擎缓存 `_space_engines[db_name]` | 删除后须**同步驱逐**该缓存条目，避免重连已销毁的数据库 |

> **已知边界（建议确认）**：因 `space_code` 在 `b01_space` 上通常存在唯一约束，已物理删除的空间其编码不可被新空间复用（否则唯一约束冲突）。本期按「删除后编码不可复用」处理；如确需复用，建议后续对唯一约束放宽至「仅约束未删除记录」，列为后续优化。

### 5.5 后端接口设计
```
DELETE /api/v1/b01/spaces/{space_id}
鉴权：require_l0（仅 L0）
成功响应：{ "code": 0, "message": "空间已删除", "data": null }
未找到：40400 NotFound（space_id 不存在或已删除）
越权：40300 Forbidden（非 L0）
```

**服务端执行顺序（建议）**：
1. 加载 `b01_space`（`deleted_at IS NULL`），不存在则 404。
2. 在实例级连接（`_server_engine()`）上执行 `DROP DATABASE IF EXISTS \`{db_name}\``。
3. DROP 成功后，更新 `b01_space`：`deleted_at = now`、`status = 已删除`、`updated_by = 当前 L0 用户`、`updated_at = now`。
4. 驱逐 `_space_engines` 中对应库的缓存连接。
5. **审计**：写入操作审计（操作人 L0 用户 ID / 用户名、空间 ID / 名称 / 编码 / 库名、操作时间、动作=物理删除）。因业务库已销毁，审计信息须落于公共库（建议复用既有审计表或新增轻量 `b01_space_delete_log`），以保证可追溯。

> 异常处理：若第 2 步 `DROP DATABASE` 失败（如数据库被占用 / 权限不足），应**中止并回滚标记**（不置 `deleted_at`），向上返回业务错误，避免元数据与物理库状态不一致。

### 5.6 审计与安全
- 物理删除属敏感操作，必须记录操作人、时间、被删空间标识（见 §5.5）。
- 禁止在日志 / 响应中打印明文密码或敏感字段（沿用配套文档 §7.2）。
- 接口严格 `require_l0`，杜绝 L1/L2 越权删除。

## 6. 非功能性约束

### 6.1 密码复杂度（沿用配套文档 §7.1）
- 长度 ≥ 8 位；至少包含「大写字母、小写字母、数字、特殊字符」中的三类。
- 自助改密与强制改密共用同一策略校验。

### 6.2 统一响应与分层（沿用 CODEBUDDY.md §5）
- 接口统一返回 `{ code, message, data, trace_id }`。
- 后端按 router → service → repository → model 分层；跨层用 Pydantic Schema 传递。

### 6.3 界面视觉
- 弹窗、按钮、确认框样式对齐 `CODEBUDDY.md` §6.4 设计令牌（主色 `#1a73e8`、危险红 `#e53935`、对话框圆角 `10px`、遮罩 `rgba(20,30,45,0.45)` 等）。
- 「删除」按钮使用危险语义样式（文字红 / `type=danger`），与成员 / 编辑等常规操作区分。

## 7. 验收标准

| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| UR-01 | 头像下拉出现「修改密码」 | 登录任意角色后，下拉菜单含「修改密码」项，位于「退出登录」上方 |
| UR-01 | 改密成功保持登录 | 输入正确的原密码 + 合规新密码，提示成功且**不跳转登录页**，后续操作仍带有效令牌 |
| UR-01 | 改密校验 | 原密码错误 / 新密码不合规 / 两次不一致时，后端或前端拦截并提示 |
| SP-01 | 进入项目入口 | 管理列表每行均有「进入项目」，点击跳转 `/space/{id}` 且能正常加载空间工作台 |
| SP-02 | 删除按钮可见性 | 仅 L0 账号在管理列表看到「删除」；L1/L2 不可见 |
| SP-02 | 强确认 | 不输入 / 输入错误的空间名时「确认删除」禁用；输入完全一致方可点击 |
| SP-02 | 物理删库 | 确认后空间库 `mig_<code>_db` 被 DROP（实例中库消失）；后端缓存同步清理 |
| SP-02 | 元数据保留 | `b01_space` 记录仍存在但 `deleted_at` 非空、`status=已删除`；成员角色绑定保留；该空间从活跃列表消失 |
| SP-02 | 越权拦截 | 非 L0 直接调用 `DELETE /b01/spaces/{id}` 返回 40300 |
| SP-02 | 审计 | 删除操作留有审计记录（操作人 / 空间标识 / 时间） |

## 8. 已确认决策汇总（2026-10-23）

| 编号 | 议题 | 决策 |
