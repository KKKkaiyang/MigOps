## 1. 概述

### 1.1 背景与目标
任务迁移现有数据模型（`b04_task`，见《项目空间业务功能需求》§6.5.2）以一张宽表承载全部字段，并采用 `migration_status`（10 态串行状态机）+ `schedule_status` + `check_status` 三套状态。实际项目中暴露三类问题：

1. **字段僵化、难以适配不同项目的差异化管理**：各迁移项目的关注字段差异大（如有的项目关注"任务分级""源端集群"，有的不关注），宽表无法灵活增删，且列顺序 / 列表展示无法按项目定制。
2. **状态维度混杂、约束过死**：旧 `migration_status` 将迁移 / 调度 / 校验 / 验收揉进一条串行状态机，无法并行表达"已迁移但校验不通过仍在双跑"等真实状态组合。
3. **导入列固定、无法按项目裁剪**：现有 Excel 导入固定列，无法按项目只导入其关心的字段。

本需求将 `b04_task` 拆分为**基础表（固定核心字段）+ 扩展表（按项目动态扩展列）**两张表，并引入**空间级迁移模板**统一管理"哪些字段参与、是否必填、排序与列表展示、导入列规则"，使每个迁移项目都能按自身管理逻辑定制任务台账，同时保留平台统一的状态语义与空间隔离。

### 1.2 范围
| 能力 | 归属 | 本期范围 |
| --- | --- | --- |
| 数据模型拆分 | `b04` | `b04_task`（基础表） + `b04_task_ext`（扩展表，一对一） |
| 基础表字段重定义 | `b04` | 15 个业务字段 + `task_uri`（唯一键）+ 审计字段，详见 §3 |
| 5 维独立状态 | `b04` | 任务活跃 / 迁移 / 双跑调度 / 数据校验 / 客户验收，各独立取值，详见 §3 |
| 扩展表 + 动态扩展字段 | `b04` | 枚举类（默认建索引）/ 字符串类（默认 VARCHAR(255)），按模板动态加列 `f_1…n` |
| 空间级迁移模板 | `b04` | 字段选择（必填锁定 8 项）+ 排序 + 列表展示开关 + 扩展字段定义；每空间一份 |
| 列表展示与排序 | `b04` | 默认按模板顺序；标签列作为特殊列始终末位 |
| 导入按模板规则 | `b04` | 强制先配模板；导入 Excel 列由模板生成；保留覆盖 / 增量两种模式 |
| 字段互填规则 | `b04` | 工作流名称 / 任务名称不能全空，空其一则用另一者填充 |

**不在本期范围**：
- 模板按"场景"差异化（本期模板为**空间级**，适用于该空间全部场景；按场景拆分列为后续扩展，见 §10 A1）；
- 扩展字段的版本化 / 历史追溯（扩展列变更直接 ALTER，不做字段级变更日志）；
- 在线文档导入（已作废，见总文档 §10.3）的重启；若重启须同样遵循本模板规则（§10 A5）；
- `b04_task_note`（排查备注）、`b04_saved_view`（自定义台账）、`b04_tag`（标签）的存储结构重构——本需求仅调整任务主体表与模板，台账 / 标签 / 备注表保持不变，仍引用 `b04_task.id` 作为单一真实来源。

### 1.3 术语
| 术语 | 含义 |
| --- | --- |
| 迁移任务基础表 | `b04_task`，承载所有项目共有的核心业务字段（固定列） |
| 迁移任务扩展表 | `b04_task_ext`，与基础表**一对一**，按空间模板动态新增列 `f_1…n` 承载项目个性字段 |
| 空间级迁移模板 | `b04_migration_template`，每空间一份，定义字段集合 / 必填 / 顺序 / 列表展示 / 扩展字段定义 |

| 标签列（特殊列） | 复用既有 `b04_tag` 标签系统；在任务列表作为**特殊列始终展示在最后一列**，不受模板排序影响 |
| 5 维状态 | 任务活跃状态 / 迁移状态 / 双跑调度状态 / 数据校验状态 / 客户验收状态，彼此独立、互不约束 |

## 3. R-02 基础表字段定义（`b04_task`）

### 3.1 表结构（空间库 `mig_<space_code>_db`）
基础表 = 所有项目共有的固定列；扩展字段一律不进基础表（见 R-03）。除业务字段外，保留 `space_id` / `scenario_id`（迁移项目空间 id、场景 id）与审计字段（`created_by` / `created_at` / `updated_by` / `updated_at` / `deleted_at`，遵循 `CODEBUDDY.md` §3.3）。

| 字段 | 类型 | 约束 | 显示名 | 取值 / 说明 |
| --- | --- | --- | --- | --- |
| `id` | BIGINT | PK 自增 | — | 主键 |
| `space_id` | BIGINT | 非空 | — | 所属迁移空间 |
| `scenario_id` | BIGINT | 非空 | — | 所属迁移场景 |
| `project_name` | VARCHAR(128) | 非空，默认 `default` | 项目名称 | 任务在数据开发治理平台归属的**项目空间**；默认 `default`（由旧 `dw_project_space` 统一改名而来，见 D2） |
| `workflow_name` | VARCHAR(128) | 可空 | 工作流名称 | 归属工作流；与 `task_name` 不能全空（互填规则，见 §3.3） |
| `task_name` | VARCHAR(255) | 非空 | 任务名称 | 具体任务名；与 `workflow_name` 不能全空 |
| `env` | VARCHAR(32) | 非空，默认 `生产` | 归属环境 | 开发 / 测试 / 准生产 / 生产 |
| `business` | VARCHAR(255) | 可空 | 归属业务 | 选填 |
| `task_type` | VARCHAR(64) | 可空 | 任务类型 | 码值形式（DI / HiveSQL / SparkSQL / HoloSQL / ODPSSQL / StarRocks 等），各项目码值集不确定，存原始码值 |
| `migration_owner` | VARCHAR(64) | 非空 | 迁移 Owner | 迁移负责人 |
| `active_status` | VARCHAR(32) | 非空，默认 `草稿` | 任务活跃状态 | 草稿 / 正常调度 / 下线 / 冻结 |
| `migration_status` | VARCHAR(32) | 非空，默认 `未开始` | 迁移状态 | 未开始 / 迁移中 / 已完成 |
| `dualrun_status` | VARCHAR(32) | 非空，默认 `未调度` | 双跑调度状态 | 未调度 / 调度中 / 空跑调度 / 提交报错 |
| `check_status` | VARCHAR(32) | 可空 | 数据校验状态 | 校验通过 / 校验不通过 / 微小差距（初始可空，视作"未校验"；作为必填项导入时必须填其一，见 §10 A4） |
| `acceptance_status` | VARCHAR(32) | 可空 | 客户验收状态 | 通过 / 不通过（初始可空，视作"未验收"） |
| `remark` | VARCHAR(1024) | 可空 | 备注信息 | 最后一次备注的状态 |
| `task_uri` | VARCHAR(512) | 非空，唯一 | 任务 URI | 由 `项目名称://任务名称@工作流名称` 生成；唯一约束 `(scenario_id, task_uri)`（D3 保留，作唯一键与血缘关联键） |
| 审计字段 | — | 必填 | — | `created_by` / `created_at` / `updated_by` / `updated_at` / `deleted_at` |

> 唯一约束：`(scenario_id, task_uri)`（未删除）。逻辑删除沿用 `deleted_at`（NULL = 未删）。

### 3.2 5 维状态说明（整体替换旧模型，D1）
下表明确新状态维度与旧模型（`migration_status` 10 态 / `schedule_status` / `check_status`）的替换关系；旧状态机（`CODEBUDDY.md` 旧 BRD 4.2）随之废弃。

| 新维度 | 列名 | 取值 | 替代的旧字段 |
| --- | --- | --- | --- |
| 任务活跃状态 | `active_status` | 草稿 / 正常调度 / 下线 / 冻结 | 新增维度（旧模型无对应） |
| 迁移状态 | `migration_status` | 未开始 / 迁移中 / 已完成 | 旧 `migration_status`（10 态状态机） |
| 双跑调度状态 | `dualrun_status` | 未调度 / 调度中 / 空跑调度 / 提交报错 | 旧 `schedule_status`（未提交/已提交/调度中/调度成功/调度失败） |
| 数据校验状态 | `check_status` | 校验通过 / 校验不通过 / 微小差距 | 旧 `check_status`（未校验/校验中/校验通过/校验不通过） |
| 客户验收状态 | `acceptance_status` | 通过 / 不通过 | 旧并入 `migration_status` 的验收态（客户验收通过/不通过） |

- 五个维度**彼此独立、互不约束**：例如可同时处于 `migration_status=已完成` 且 `check_status=校验不通过` 且 `dualrun_status=空跑调度`，以贴合真实迁移并行状态。
- 状态流转校验：旧"非法流转前端提示、后端拦截"的**串行状态机校验逻辑废弃**；新模型各维度独立，单次更新仅校验该维度取值在枚举内（不做跨维度流转合法性约束，除非后续业务明确补充，见 §10 A4）。
- 颜色编码（沿用 `CODEBUDDY.md` §6.4.2 语义配色）：迁移 / 校验 / 验收等状态采用"颜色 + 文字标签"双标识（通过=绿、不通过/报错=红、微小差距/待关注=黄、未开始/未调度=灰）。

### 3.3 工作流名称 / 任务名称互填规则
- 二者不能**同时为空**；
- 若 `workflow_name` 为空，`task_uri` 与展示以 `task_name` 填充工作流部分（或留 `default` 工作流）；
- 若 `task_name` 为空，则以 `workflow_name` 填充 `task_name`；
- 落库前由后端保证至少其一非空，否则拒绝导入 / 新增并提示。

### 3.4 与旧字段的取舍（D3）
- **保留**：`task_uri`（唯一约束 + 血缘关联键，见 §9.8 影响）。
- **移出基础表**：
  - `script_name`：不再作为基础表标准列；如某项目需要，可用**字符串类扩展字段**承载（见 R-03）。
  - `input_tables` / `output_tables`：不再作为基础表字段；任务详情"输入表 / 输出表"清单已统一由 B04-03 血缘关联（`b07_lineage`）取得（按 `项目名称` + `task_name` 关联，过滤临时表），见 §9.8 影响。

## 4. R-01 / R-03 扩展表与动态扩展字段（`b04_task_ext`）

### 4.1 一对一关系
`b04_task_ext` 与 `b04_task` **业务上严格一对一**，通过 `task_id`（= `b04_task.id`）关联；扩展表主键即 `task_id`（外键级联）。基础表一行对应扩展表至多一行（未配置扩展字段的项目其任务在扩展表无行亦可，查询 LEFT JOIN）。

### 4.2 动态加列（D4）
- 扩展字段分为两类，由空间模板定义（见 R-04）：
  - **枚举类**：存码值；数据库**默认建索引**（`idx_f_n`），便于按扩展字段筛选；
  - **字符串类**：数据库**默认 VARCHAR(255)**。
- 每个扩展字段在扩展表中**增加一列**，列名由后端建表 / 改表时**自动生成** `f_1`、`f_2` … `f_n`（按模板定义的扩展字段顺序编号，与 `config_json` 中扩展字段序号一一对应）。
- 物理落地：**每个空间库 `mig_<space_code>_db` 各自持有 `b04_task_ext`**，新增 / 修改空间模板中的扩展字段时，后端对该空间库执行 `ALTER TABLE b04_task_ext ADD COLUMN f_n ...`（同一空间内扩展列仅本空间可见，符合空间隔离，D4）。
- 建议扩展列上限 ≤ 30（见 §10 A3），防止单表列膨胀。

### 4.3 表结构（空间库，动态列）
| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `task_id` | BIGINT | PK / FK → `b04_task.id` | 一对一关联 |
| `f_1` | 枚举→(码值列+索引) / 字符串→VARCHAR(255) | 可空 | 模板定义的第 1 个扩展字段（中文名由模板维护） |
| `f_2` … `f_n` | 同上 | 可空 | 依次类推，由模板动态生成 |

> 扩展字段的**中文显示名**存于空间模板 `config_json`（见 R-04），数据库仅存英文列 `f_n` 与值；前端按模板映射回中文名展示。

## 5. R-04 空间级迁移模板（`b04_migration_template`）

### 5.1 表结构（空间库）
| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK 自增 | 主键 |
| `space_id` | BIGINT | 非空，唯一 | **每空间一份**模板 |
| `name` | VARCHAR(128) | 非空 | 模板名称 |
| `config_json` | JSON | 非空 | 字段配置（有序），结构见 §5.2 |
| 审计字段 | — | 必填 | 同上 |

### 5.2 `config_json` 结构
```json
{
  "fields": [
    {
      "field_key": "project_name",        // 基础表字段名 或 扩展字段序号 "ext_1"
      "field_label": "项目名称",            // 中文显示名（扩展字段的中文名在此定义）
      "field_source": "base",              // base=基础表字段；extension=扩展字段
      "is_required": true,                 // 是否必填（导入必须有值）
      "display_in_list": true,             // 是否在查询列表展示
      "order": 1,                          // 排序（升序）
      "ext_type": null,                    // 仅 extension：enum（枚举）/ string（字符串）
      "enum_options": null                 // 仅 enum：[{code,label}, ...]，见 §5.4
    },
    { "field_key": "ext_1", "field_label": "任务分级", "field_source": "extension",
      "is_required": false, "display_in_list": true, "order": 9,
      "ext_type": "enum", "enum_options": [{"code":"P0","label":"P0"},{"code":"P1","label":"P1"}] }
  ]
}
```

### 5.3 字段选择与必填规则
- 模板从**基础表 15 个业务字段**中选择参与字段；**必选项锁定不可取消**，包括：
  `项目名称、任务名称、迁移负责人（migration_owner）、任务活跃状态、迁移状态、双跑调度状态、数据校验状态、客户验收状态`（共 8 项）。
- 其余基础字段（工作流名称、归属环境、归属业务、任务类型、备注信息）可按项目实际**选择是否纳入**模板。
- 被模板"未选择"的基础字段：不出现在导入 Excel、列表默认不展示、导入时按空处理（可选字段允许空，见 §10 A2）。
- **必填语义（D5）**：必填 = 必须纳入模板 + 导入必须有值；但**列表展示可任意开关**（8 项必填不强制展示，可设为 `display_in_list=false`，仅详情可见）。

### 5.4 扩展字段定义（含枚举选项，D6）
- 模板中可追加扩展字段：定义**中文名** + 类型（enum / string）；后端据类型在 `b04_task_ext` 加 `f_n` 列。
- **枚举类选项维护方式（D6）**：采用"**首次导入动态收集**"——不在模板预定义码值清单，导入时遇到的新值自动加入该枚举的选项集（前端下拉后续即出现该值）；导入取值不在历史选项集时自动并入（仍受 ext_type=enum 约束，存码值）。
- 字符串类：自由文本，默认 VARCHAR(255)。

### 5.5 模板配置入口
- 空间内任务迁移模块提供「迁移模板配置」入口（L0/L1 可维护，等同空间内业务操作权限）；
- 同一空间仅一份模板；修改模板（增删扩展字段、改排序 / 展示 / 必填）即时影响后续导入与列表；
- **扩展字段增减触发后端 ALTER TABLE**（D4）；删除扩展字段需谨慎（历史数据该列清空或保留，见 §10 A3）。

---

## 6. R-05 列表展示与排序

- **默认排序**：任务列表查询**默认按模板 `config_json` 中 `order` 升序**展示字段（前端读取模板顺序渲染列）。
- **标签列特殊列**：任务列表的「标签」列复用既有 `b04_tag` 标签系统，**作为特殊列始终展示在最后一列**，不受模板排序影响（需求原文："标签列属于特殊列，展示在最后一列"）。
- **列显隐**：每个字段的 `display_in_list` 控制是否在列表展示；关闭则仅在任务详情可见。
- **筛选**：仍支持按工作流 / 各状态 / Owner / 标签（AND·OR）组合筛选；扩展字段（枚举类，已建索引）支持按 `f_n` 值筛选（字符串类扩展字段是否支持筛选为可选实现）。

## 7. R-06 导入按模板规则

### 7.1 强制先配模板（D7）
- **空间未配置迁移模板时，禁止导入，也禁止下载导入 Excel 模板**（提示"请先配置迁移模板"）。
- 模板配置完成后，导入与下载均按模板规则执行。

### 7.2 导入 Excel 列生成
- **下载的导入模板 Excel** 与**实际导入解析**的列，均由模板 `config_json` 按 `order` 升序生成（仅含被模板选中的字段；扩展字段以其中文名作表头，映射回 `f_n`）。
- 导入校验：
  - 必填项（`is_required=true`）缺失 → 行级报错；
  - 工作流 / 任务名称互填规则（§3.3）；
  - 状态字段取值须在对应维度枚举内；
  - 枚举类扩展字段取值按 D6 动态收集。
- **覆盖导入 / 增量导入两种模式均保留**（沿用上位需求 §6.4.2），按 `task_uri` 判定新增或更新。

### 7.3 导入接口影响
- 现有 `POST /b04/scenarios/{id}/import`（覆盖 / 增量）改为**按模板字段解析**（列以模板为准，不再固定旧 8 列）；未配模板时拒绝（HTTP 业务错误，提示先配模板）。
- 新增 `GET /b04/templates/import-excel`：按当前空间模板生成并下载导入 Excel（列按模板顺序）。

## 8. 后端接口与数据变更要点
- 新增 `b04_migration_template` 表（每空间一份，`config_json`）；模板 CRUD 接口（归入 `/api/v1/b04`）。
- 模板保存 / 修改扩展字段时，对当前空间库 `b04_task_ext` 执行 `ALTER TABLE ... ADD COLUMN f_n`（enum→带索引列，string→VARCHAR(255)）；删除扩展字段时 `DROP COLUMN`（或保留并置空，见 A3）。
- 任务列表接口 `GET /b04/scenarios/{id}/tasks` 返回结果：
  - 字段顺序与展示由模板驱动（含扩展字段 `f_n` → 按 `config_json` 映射中文名）；
  - 标签列在末位；
  - 支持按模板扩展字段（尤其枚举类）筛选。
- 导入接口改造（§7.3）：按模板字段解析，强制模板前置。
- 统一响应 `{ code, message, data, trace_id }`；分页 `{ list, total, page, page_size }`（沿用 `CODEBUDDY.md` §5）。

## 9. 非功能性约束

### 9.1 统一响应与分层（沿用 CODEBUDDY.md §5）
- 接口统一返回信封；router → service → repository → model 分层；跨层 Pydantic Schema 传递。

### 9.2 界面视觉（沿用 CODEBUDDY.md §6.4）
- 主色 `#1a73e8`、危险红 `#e53935`、对话框圆角 `10px`、遮罩 `rgba(20,30,45,0.45)`；状态采用"颜色 + 文字标签"双标识（§3.2）。
- 标签胶囊：圆角 `10px`、字号 `11px`、色块 + 文字（`§6.4.2`）。

### 9.3 空间隔离与数据归属（沿用既有）
- `b04_task` / `b04_task_ext` / `b04_migration_template` 均存空间库 `mig_<space_code>_db`，查询与写入强制按当前空间过滤。
- 扩展列仅本空间可见（D4）；`task_uri` 关联血缘（`b07_lineage`）随空间隔离。

### 9.4 动态 DDL 安全
- 扩展列 `f_n` 名称由系统生成、白名单化（仅 `f_` + 数字），防止 SQL 注入；ALTER 操作需限频 / 事务化，避免并发改表。

### 10.1 待复核假设（A1~A6，建议复核）
- **A1**：模板为**每空间一份**（空间级，适用该空间全部场景）；若未来需按场景差异化模板，再行扩展。
