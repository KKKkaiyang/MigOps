## 1. 概述

### 1.1 背景与目标
数据迁移项目中，表与表之间的加工（读写）关系构成数据血缘。团队成员常用脚本（SQL / PySpark）描述加工逻辑，并希望平台能**自动解析脚本抽取血缘**、以**检索驱动的分层视图直观展示**、并支持**按表检索上下游**。

参考实现 `tools/hrwx_lineage` 已验证一套成熟可用的血缘能力（检索驱动分层展示、按表检索、节点展开/收起、右键下钻、检索感应提示、脚本解析、按工作流新增/重建），其视觉风格即本项目 §6.4 设计令牌的来源。**本期不再将其视为「血缘图谱（全量自动布局网络图）」，而是直接复刻其「检索驱动 + 手写 SVG」的展示与交互**，按当前项目规范重构为 `b07` 模块：后端 FastAPI + SQLAlchemy 分层、统一响应信封；前端 Vue 3 + TS + Element Plus；数据按空间库隔离。

### 1.2 范围
| 能力 | 归属 | 本期范围 |
| --- | --- | --- |
| 血缘可视化查询 | `b07` | **检索驱动**：选中表后以该表为根，左→右分层展示上下游；节点按表类型着色；节点 `+/−` 展开收起；缩放/平移/适应/PNG 导出；纯颜色图例（无开关） |
| 血缘检索 | `b07` | 顶部检索栏**感应提示**（表名 + 工作流名）；选中后设为当前表并展开上游一度；节点 `+/−` 与右键全量下钻/收起 |
| 节点/边详情 | `b07` | 节点看写入/读取任务（工作流/任务/脚本/项目/类型）；右键边看读写关系与来源任务 |
| 血缘新增 | `b07` | 解析 SQL/PySpark 脚本 → 预览 → 按工作流入库（add 模式） |
| 血缘重建 | `b07` | 解析脚本 → 逻辑删除该工作流旧边并重新入库（rebuild 模式） |
| 脚本解析引擎 | `b07` | 移植参考 `lineage_parser`：支持 SQL + PySpark，输出 `input→output` 边 |

**不在本期范围**：
- 数据校验（validation）相关：校验结果导入、节点校验状态着色、校验浮层（归属 `b05`）。
- 跨空间血缘合并：血缘按空间库隔离，不做跨空间聚合。
- 手动单条边的逐字段录入界面（本期以「脚本解析」为唯一建血缘入口；后续可扩展）。
- 血缘版本历史 / 时间快照对比。

### 1.3 术语
- **血缘边（edge）**：一条 `input_table → output_table` 的读写关系，数据由输入表流向输出表。
- **正式表 / 临时表**：表类型。临时表仅在同「工作流 + 脚本」上下文内与上下游关联；正式表按表名全局关联。**本期临时表默认始终渲染，不提供显隐开关**（见 D6）。
- **工作流（workflow）**：血缘的组织单元；新增/重建均按工作流维度操作（重建 = 删除该工作流全部旧边后重入）。
- **上游 / 下游**：相对当前表，上游 = 写入当前表的来源表；下游 = 当前表写入的目标表（与数据流向一致）。
- **当前表（聚焦表）**：检索选中的根节点，绿色描边。

## 3. 功能设计

> 下表为需求功能点（R1–R5），与决策 D1–D6 一一对应。

### R1 血缘可视化查询（检索驱动，复刻参考）
- **进入即请求数据、但画布初始为空态**：加载当前空间全量血缘边（`GET /lineages`），前端 `buildGraph` 构建邻接索引；画布初始显示空态提示「请输入表名进行血缘检索」。
- **检索驱动渲染**：用户在检索栏选中某表（或工作流入口表）后，该表成为「当前表（聚焦表）」并作为**根节点**，以**左→右分层 DAG** 展示其上游（左）/ 下游（右）。**不再采用「进入即加载全部边自动布局成网络图谱」的方式**（否决 V1.0 的 g6 全量图谱方案）。
- **节点着色（对齐 §6.4.2）**：正式表 = 蓝填充 `#e8f0fe` / 描边 `#1a73e8`；临时表 = 琥珀橙填充 `#fef7e0` / 描边 `#f2a100`；当前聚焦表 = 绿色描边 `#188038`。节点为圆角矩形，显示「库名 + 表名」两行（超长省略，hover 显示全名）。
- **节点展开 / 收起特效（必须对齐参考实现）**：
  - 每个节点左（上游）/ 右（下游）各有一个 `+/−` 圆形切换按钮，并带**邻居数量角标**；点击展开/收起该方向一度。
  - 仅「可达方向」显示切换按钮：检索入口当前表支持双向；由上游展开到达的节点只能继续向上；由下游到达的只能继续向下（防止反向串扰）。
  - 右键节点菜单：**查看详情 / 展开上游全部 / 收起上游 / 展开下游全部 / 收起下游**。
  - **缓动居中**：展开/收起时整个图层以 `transition: transform 0.4s cubic-bezier(0.22,0.61,0.36,1)` 平滑平移，使「被展开子树」或「全部可见血缘」居中（`centerOnExpansion` / `centerOnAll`）；**拖拽平移时关闭过渡以保证跟手**（对齐参考 `LineageGraph.vue`）。
- **画布交互**：缩放（`+/−` 与滚轮，缩放范围 0.2–2.5）、适应屏幕、重置视图、拖拽平移、PNG 导出（SVG→Canvas，底色 `#eef2f7`）。
- **高亮**：hover 节点高亮其直接上下游一度邻居（蓝色加粗、箭头变蓝），其余节点/连线淡化；移出恢复。
- **图例（D6）**：仅颜色图例——正式表 / 临时表 / 当前表。**不再包含任何开关控件**（「显示临时表」「显示未知工作流」均已移除）。

### R2 血缘检索（抄参考 SearchBar 感应提示）
- 顶部检索栏（`SearchBar`，**直接复刻参考实现**）：
  - 输入即出**下拉感应提示**：建议项包含 **正式表名**（短名 + 全名 + 类型徽标 + 项目标签 + 任务类型标签）与 **工作流名**（⚙ 图标 + 涉及表数 + 入口表）；支持 **↑/↓ 键导航、回车确认、点击选择**。
  - **仅检索正式表**（临时表不进入建议，与参考一致）；工作流名也参与匹配（选中后跳转至其入口表再由用户下钻）。
  - 无匹配时显示「未找到匹配的表或工作流」。
  - placeholder：「输入表名或工作流名称检索血缘」。
- 选中表 → 设为「当前表」，**默认展开上游一度**血缘；下游一度由用户在节点上点击 `+/−` 展开。
- 点击节点高亮其直接上下游一度邻居；右键节点菜单下钻/收起。
- 临时表按其所属「工作流 + 脚本」上下文展开（不串到其他工作流）。

### R3 节点 / 边详情
- **节点详情面板**（右侧浮层，对齐 §6.4.6 浮层样式）：表全名；选项卡「写入任务 / 读取任务」。每条任务展示：任务名、项目、任务类型、脚本（可复制）、对侧表名（顿号分隔）；按工作流分组、默认折叠、点击展开。
- **边详情**（右键连线浮层）：读写关系（读取表 → 写入表，上游读/下游写语义着色，对齐 §6.4.2 上游琥珀 `#c2a36b` / 下游蓝 `#1a73e8`）；来源任务（工作流/任务/脚本）。
- **复制**：节点 / 工作流 / 脚本名支持一键复制（对齐参考交互，复制后图标变绿短暂反馈）。

### R4 血缘新增（按工作流解析脚本入库）
- 「工作流管理」菜单 → 「新增工作流血缘」→ `WorkflowDialog`（**复刻参考**）：
  - 录入：工作流名称（必填）、任务名、任务类型、项目名、脚本路径/名称；
  - 血缘来源：**粘贴脚本代码** 或 **上传脚本文件**（SQL / PySpark）；
  - 可选「默认库名」：为无库名前缀的正式表自动补 `default_db.` 前缀（幂等）；
  - 点击「解析预览」→ 后端 `/parse` 返回边列表，对话框内预览（源→目标、类型）；
  - 确认「入库」→ 后端 `/import`（mode=add）逐条写入 `b07_lineage`（`workflow_name` 等元信息附加到每条边）。
- 仅保留 `source` 与 `target` 均非空的边入库。

### R5 血缘重建（按工作流覆盖）
- 「工作流管理」菜单 → 「重建工作流血缘」→ 同 `WorkflowDialog` 但 mode=rebuild：
  - 选择已有工作流（后端 `/workflows/{name}/options` 返回该工作流的 任务/脚本/任务类型/项目 用于预填）；
  - 解析脚本后，**先逻辑删除（置 `deleted_at`）该工作流全部旧边**，再写入新边；
  - 保证同一工作流血缘与最新脚本一致。

## 4. 数据模型

### 4.1 表命名与归属
- 库：`mig_<space>_db`（空间库，D1）；前缀 `b07_`。
- 表：`b07_lineage`（血缘边主表）。本期单表设计，按 `workflow_name` 聚合实现新增/重建；若后续需更强审计可扩展 `b07_lineage_batch` 批次头表（非本期）。

### 4.2 字段映射（参考 `data_lineage_hr.lineage` → `b07_lineage`）
| 参考库字段 | 新表 `b07_lineage` 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | `id` | BIGINT 自增 | 主键 |
| `workflow_name` | `workflow_name` | VARCHAR(255) | 工作流名称 |
| `task_name` | `task_name` | VARCHAR(255) | 任务名 |
| `task_type` | `task_type` | VARCHAR(64) | 任务类型（SQL/PySpark/导出…） |
| `project_name` | `project_name` | VARCHAR(255) | 所属项目 |
| `script_name` | `script_name` | VARCHAR(512) | 脚本路径/名称 |
| `input_table` | `input_table` | VARCHAR(512) NOT NULL | 输入表（源） |
| `input_table_type` | `input_table_type` | VARCHAR(32) | 输入表类型：正式表 / 临时表 |
| `output_table` | `output_table` | VARCHAR(512) NOT NULL | 输出表（目标） |
| `output_table_type` | `output_table_type` | VARCHAR(32) | 输出表类型：正式表 / 临时表 |
| — | `created_by` / `created_at` / `updated_by` / `updated_at` | — | 审计字段（规范 §3.3） |
| — | `deleted_at` | datetime NULL | 逻辑删除（重建时置位） |

**索引**：`idx_b07_workflow(workflow_name)`、`idx_b07_input(input_table)`、`idx_b07_output(output_table)`。
**约束**：`input_table` / `output_table` 非空；类型枚举存中文（正式表/临时表），展示由前端映射着色。
> 注：D6 仅影响前端显隐，**不改变数据模型**；临时表与未知工作流数据照常存储，仅前端默认全部渲染临时表、隐藏未命名工作流（且无切换开关）。

### 4.3 ORM 与引擎
- `app/models/b07_lineage.py`：`B07Lineage`（Base = 空间库 `SpaceBase`）。
- 后端通过 `get_space_db` 获取空间 session；`DB_TYPE` 路由同既有模块。

## 5. 后端变更要点

### 5.1 分层与路由
- 路由 `app/routers/b07_lineage.py`，路径前缀 `/api/v1/b07`：
  - `GET  /lineages` — 列表当前空间**全部**边（支持筛选 workflow / keyword(表名模糊) / table_type）；用于前端一次性取全量边并客户端构图（检索驱动，对齐参考「先全量取、后检索渲染」）。
  - `POST /lineages/parse` — 解析脚本：`{code|file, lang}` → 返回 `edges[]`（预览）。
  - `POST /lineages/import` — 入库：`{workflow, task?, task_type?, project?, script_name?, mode:add|rebuild, default_db?, edges?|code?, lang?}`；`mode=rebuild` 先逻辑删除该工作流旧边再插入。
  - `GET  /lineages/workflows` — 列出工作流（去重）+ 各工作流涉及表数 / 入口表（汇聚点）。
  - `GET  /lineages/workflows/{workflow}/options` — 该工作流下 任务/脚本/任务类型/项目 去重列表（重建预填）。
  - `DELETE /lineages/{id}` — 逻辑删除单条边（修正误录）。
- 服务 `app/services/b07_lineage.py`：封装列表、解析入库、`rebuild`、工作流聚合。
- 解析引擎 `app/utils/lineage_parser.py`：移植参考 `lineage_parser`（SQL + PySpark），输出 `[{source,target,source_type,target_type}]`；`lang` 显式指定或启发式自动识别。

### 5.2 统一响应
所有接口返回 `{code,message,data,trace_id}`；错误经全局异常处理器转换；解析失败 / 脚本为空返回 `code!=0` 业务错误。

### 6.3 渲染方案与样式对齐（不引入图库）
- **不使用 `@antv/g6` / `vis-network` 等图可视化库**：直接复刻参考的**手写 SVG + 参考 layout 算法**（左→右分层树布局，正交折线 `M..L..L..L`，箭头方向指向数据流向）。理由：参考交互（节点 `+/−` 展开收起、右键全量下钻、缓动居中、检索感应）均为定制逻辑，图库反而难以对齐；且 §6.4 设计令牌本就提炼自该参考实现。
- **样式须对齐 §6.4 设计令牌**：正式表蓝填充/描边、临时表琥珀、聚焦绿描边；上游箭头琥珀、下游箭头灰蓝；浮层圆角 `10px`、阴影 `0 8px 24px`、白底；字号阶梯（节点表名 `10px`、辅助 `11~12px`）；复制/搜索反馈态；图例 `z-index:20`、浮层 `30~60`、对话框 `1000`、Toast `1100`（对齐 §6.4.7）。
- 导出 PNG：SVG→Canvas（底色 `#eef2f7`），对齐参考导出交互。

### 6.4 API 封装

## 7. 验收标准
- **AC1（可视化）**：进入血缘页显示空态「请输入表名进行血缘检索」；选中表后以该表为根左→右分层展示上下游；节点按正式/临时/聚焦正确着色；节点 `+/−` 带数量角标且展开/收起带 0.4s 缓动居中、拖拽跟手；缩放/平移/适应/导出可用；图例仅颜色图例、无任何开关。
- **AC2（检索）**：检索栏输入即出感应提示（正式表 + 工作流名，含类型/项目/任务类型标签，支持键盘导航）；选中表可定位并默认展开上游一度；节点 `+/−` 与右键可下钻/收起；临时表仅在同工作流+脚本上下文展开。
- **AC3（详情）**：点击节点显示写入/读取任务（工作流/任务/脚本/项目/类型/对侧表）；右键边显示读写关系与来源任务；复制可用。
- **AC4（解析入库）**：粘贴或上传 SQL/PySpark → 预览正确血缘边；确认后按工作流写入 `b07_lineage`，列表与图同步更新。
- **AC5（重建）**：重建某工作流 → 旧边被逻辑删除、新边写入；图与列表反映最新脚本血缘。
- **AC6（隔离与规范）**：血缘数据存于 `mig_<space>_db.b07_lineage`，随空间隔离；后端返回统一信封；前端按 `b07` 分组、检索驱动手写 SVG、样式对齐 §6.4；临时表始终渲染、未知工作流默认隐藏且无切换开关（D6）。

## 8. 关联与边界
- 与 `b05` 数据校验管理：本期**不含**任何校验逻辑与着色；如后续要在血缘图叠加校验状态，应在 `b05` 提供数据、由 `b07` 消费展示，避免职责交叉。
- 与 `b04` 任务迁移：`b07` 血缘的 `workflow_name / task_name / script_name` 字段语义与任务迁移脚本同源，但本期不强制与 `b04` 任务台账联动（仅字段命名一致，便于未来打通）。
- 参考实现 `tools/hrwx_lineage` 的 `lineage_parser` 为解析逻辑唯一来源；其 `validation` 部分整体忽略。
