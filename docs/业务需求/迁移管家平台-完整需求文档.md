## 2. 平台概述

### 2.1 背景与目标

迁移管家（MigOps）是面向公有云大数据迁移项目的管理平台，以「迁移空间」为隔离单元，将大数据迁移全流程标准化、线上化、可沉淀：

```
需求调研 → 元数据/数据迁移 → 任务迁移 → 数据校验 → 客户验收
              （b03）        （b04）      （b05·二期）
```

- **基座**：用户、角色、权限与项目空间（`b01`），全功能登录态；
- **空间内业务**：项目资料索引（`b02`）、数据迁移管理（`b03`）、任务迁移管理（`b04`）、血缘管理（`b07`）；
- **辅助体系**：标签体系（服务 `b04`，UI 概念对应 `b06`）、自定义台账（任务工作清单）。

### 2.2 隔离单元与数据路由

- **同实例不同库**：公共库 `mig_common_db` 与空间库 `mig_<space_code>_db` 位于同一数据库实例，通过 engine 路由区分（`CODEBUDDY.md` §8 评审结论 4）；
- **空间创建即初始化**：创建空间时创建空间库并初始化 `b01`（空间级成员/角色表）、`b02~b05` 各模块业务表；
- **所有空间内接口按当前空间过滤**，禁止跨空间访问，越权由后端权限依赖统一拦截。

### 2.3 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Python + FastAPI（异步、OpenAPI）+ SQLAlchemy 2.0 + Pydantic v2 + Alembic（MySQL 侧） |
| 数据源 | MySQL / StarRocks 可切换（`DB_TYPE=mysql\|starrocks`） |
| 前端 | Vue 3（`<script setup>`）+ Vite + TypeScript + Element Plus + Pinia + Vue Router 4 |
| 可视化 | 血缘管理采用**手写 SVG**（不引入图可视化库，见 §5.4 D3） |
| 响应结构 | 统一信封 `{ code, message, data, trace_id }`；分页 `{ list, total, page, page_size }` |

## 4. 公共业务需求（用户 / 认证 / 角色 / 空间）

> 数据归属 `mig_common_db`；来源：《公共业务-用户权限与项目空间管理需求》V1.1。

### 4.1 用户模型（`common_user`）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK，自增 | 用户 ID |
| `username` | VARCHAR | 唯一、非空 | 登录用户名 |
| `password` | VARCHAR | 非空 | 密码密文（bcrypt/argon2 哈希） |
| `name` | VARCHAR | 非空 | 姓名 |
| `email` / `phone` | VARCHAR | 可空 | 预留 |
| `org_type` | ENUM | 非空 | 归属：内部 / 其他厂商 / 客户 / 腾讯（**仅标签，无权限差异**） |
| `status` | ENUM | 非空 | 启用 / 停用（注销 = 停用） |
| `login_fail_count` | INT | 默认 0 | 连续登录失败计数 |
| `locked_until` | DATETIME | 可空 | 账号锁定截止时间 |
| 审计字段 | — | 必填 | `created_by/at`、`updated_by/at`、`deleted_at` |

- 默认账户：`admin / Admin@1234`（L0 全局，启用）。

### 4.2 认证与登录

- 全功能**登录态**访问，未登录统一跳转登录页；
- 密码存储：bcrypt / argon2 自适应成本哈希，**仅存哈希、不存明文**（弃用初稿「用户名+密码+密钥 SHA256」方案）；
- 登录失败策略：

| 阶段 | 触发条件 | 行为 |
| --- | --- | --- |
| 验证码 | 同账号连续 3 次密码错误 | 后续登录需输入 4 位图形验证码（数字+字母，排除 `1/I/0/O`） |
| 账号锁定 | 累计失败 10 次 | 锁定 30 分钟 |
| 计数重置 | 登录成功 | 失败计数清零、解锁 |

### 4.3 用户管理（仅 L0）

- **创建**：管理员创建，用户名全局唯一，密码满足复杂度策略（≥8 位，含大写/小写/数字/特殊字符中三类）；
- **注销**：停用语义（`status=停用`），不删除记录与历史数据，可重新启用恢复；停用期间空间角色关系保留但等效无权限；
- **密码重置**：管理员生成临时密码 → 用户下次登录**强制修改**；
- **角色修改**：授予/撤销全局 L0 或空间内 L1/L2，实时生效并审计。

### 4.4 项目空间管理（`b01`）

- **空间主表 `b01_space`**（存 `mig_common_db`，`b01_` 前缀）：`space_name`（唯一）、`space_code`（唯一，小写字母+数字，正则 `^[a-z][a-z0-9_]{1,30}$`，用于派生库名）、`status`、`description`、`db_name`（固定 `mig_<space_code>_db`）、`overall_progress`（TINYINT 0~100，手工维护）、客户名称、源/目标端平台、项目起止日期等（对齐 BRD 6.1）；
- **创建**：校验名称/简称唯一 → 创建空间库 → 按模块初始化 `b01`（空间级）/`b02~b05` 业务表 → 初始状态「初始化」；
- **可见范围**：L0 看全部；L1/L2 看被加入的空间；
- **状态机**：`初始化 → 交付中 → 已验收`（终态），仅 L0/L1 可修改；
- **成员管理**：L0/L1 向空间添加/移除成员、分配空间角色。

### 4.5 API 密钥（ak/sk）通用能力

> 来源：《公共业务-aksk通用能力与接口开放需求》V1.0；与《skill 管理》SK-05/SK-06、§9.9 D2 配套。

- **定位**：ak/sk 密钥对由「skill（b08）子功能」提升为**平台级公共业务通用能力**，服务范围覆盖 b03~b08 全部接口（D1）。
- **前端入口**：仍保留在「个人中心 → API 密钥」自助管理，**不新建**「公共业务管理」菜单；每用户自管自身密钥，不依赖 L0（维持 §9.9 D2）。
- **数据**：`common_user_api_key`（`mig_common_db`），结构不变（`access_key` 唯一、`secret_key_enc` 加密、状态、最近使用时间 + 审计字段）。
- **接口**（鉴权均「登录态，仅本人」）：
  - `POST/GET /common/users/me/api-keys`：生成（secret 仅一次明文）/ 列表（掩码）；
  - `DELETE /common/users/me/api-keys/{id}`：吊销（逻辑删除）；
  - `PATCH /common/users/me/api-keys/{id}`：启用 / 停用。
- **用途示例**：ak/sk 主要用于以签名方式调用平台 REST API，完成**台账刷新（b04）**、**数据校验结果回写（b05·二期）**、**skill 上传（b08）**等自动化操作；`secret_key` 仅在生成时以明文展示一次，须立即复制妥善保存，遗失后须吊销旧密钥并重新生成（无法再次查看）。
- **双鉴权复用**：REST 调用侧（b03~b08）复用 SK-06 的 HMAC-SHA256 方案（`X-Access-Key`/`X-Timestamp`/`X-Nonce`/`X-Signature`；时间戳 ±5min、nonce 单次有效），统一由 `get_actor` 依赖判定「Bearer 或 签名」两种来源（D3）。空间隔离业务（b03~b07）经 ak/sk 调用须满足空间成员 / 角色校验（D2）。
- **配套帮助页**：为降低开发者接入门槛，个人中心新增「**API 接入帮助**」页（与「API 密钥」同区，**不新建顶部菜单**），提供 ak/sk 创建指引、Python 通用签名/调用模板、以及按板块（b03~b08，含 b05 二期前瞻）的场景化接口说明，与 Swagger（`/docs`）互补（详见 §9.11 /《公共业务-API接入帮助需求》V1.0）。

## 5. 空间内业务需求

### 5.0 空间视图框架与概览页

#### 5.0.1 概览页（`/`）

- 登录后首页，主体最上方为「我的项目空间」**Panel 区**（既有 Banner 与迁移流程说明保留在 Panel 区下方）；
- Panel 网格排布（建议三列，窄屏自适应降列），一空间一面板，展示：项目名称（加粗标题）、项目简称、空间说明（两行截断+悬浮全文）、源端平台 → 目标端平台、空间状态标签、**整体进展**（进度条+百分比）、我的角色、成员数、最近更新；
- 工具栏：项目名称/简称搜索框、空间状态筛选（全部/初始化/交付中/已验收）、「+ 创建迁移空间」按钮（仅 L0/L1）；
- Panel 右下角「进入空间」主色按钮 → 跳转 `/space/:spaceId`；
- 空态引导：L0/L1 显示「创建迁移空间」；L2 提示联系项目管理员；
- 空间列表接口需返回 `overall_progress` 与 `member_count`（成员数由成员关系聚合，不落库）。

### 5.2 数据迁移管理（b03）

#### 5.2.1 功能要点

1. **迁移场景**：空间下多场景（如 `hive 元数据迁移`、`hbase 数据迁移`），场景间隔离，支持新增/重命名/删除（删需二次确认，级联处理其下清单）；

4. **迁移过程记录**：每次迁移一条记录（迁移类型、起止时间、数据量、迁移方式、数据截止日期、状态、备注），支持手工补录与 Excel 批量导入；清单行展示记录数，点击展开该表迁移历史；
5. **筛选与导出**：库名/表名/表类型/各状态筛选；导出当前场景清单及状态为 Excel；

### 5.3 任务迁移管理（b04）

> 按迁移场景管理任务全生命周期。来源：《项目空间业务功能需求》§6、《任务迁移-任务台账需求》、《任务迁移-标签管理与标签化台账需求》。

#### 5.3.1 任务台账（`b04_task`）

> ⚠️ **本小节描述的 `b04_task` 字段与三态状态机已被《任务迁移-任务台账数据模型重构需求》V1.0（§5.3.7）重构**：原单表拆分为 `b04_task`（基础表）+ `b04_task_ext`（扩展表），旧 `migration_status`/`schedule_status`/`check_status` 三态被 5 个独立状态维度取代，`dw_project_space` 统一为 `project_name`。下文保留为历史基线，权威以 §5.3.7 与碎片文档为准。

1. **迁移场景**：空间下多场景（如 `hive→hive`、`holo→starrocks`、`maxcompute→dlc`），场景间隔离；
2. **导入**：Excel/CSV 导入（工作流名称、任务名称、脚本名称、Owner、迁移状态、调度状态、数据校验状态、输入表、输出表），支持**覆盖导入与增量导入**，模板下载；导入时自动生成任务 URI（`项目名称://任务名称@工作流名称`，空间内唯一，唯一约束 `(scenario_id, task_uri)`）；
3. **列表**：表格展示核心字段，分页/排序/列显隐；
4. **状态流转**：
   - 迁移状态：未开始 / 改造完成 / 调度成功 / 数据校验通过 / 数据校验不通过 / 客户验收通过 / 客户验收不通过 / 挂起 / 废弃；
   - 调度状态：未提交 / 已提交 / 调度中 / 调度成功 / 调度失败；
   - 校验状态：未校验 / 校验中 / 校验通过 / 校验不通过；
   - 单个/批量更新，非法流转前端提示、后端拦截（挂起/废弃为旁路态）；
5. **筛选**：任务名称、工作流、迁移状态、调度状态、校验状态、Owner、**标签**（含全部=AND / 任一=OR）组合筛选；
6. **导出**：当前筛选结果导出 Excel，与页面展示一致。

#### 5.3.2 任务详情与排查备注（`b04_task_note`）

- 详情展示任务全部字段、状态变更历史、排查备注时间线；
- 备注类型：`troubleshoot`（排查备注）/ `check_result`（校验结果）；含备注时间、备注人、问题描述（排查类必填）、原因分析、修复方案；
- 时间线按时间正序（最新在下），不可删除（审计完整），可追加补充。

#### 5.3.3 自定义台账（`b04_saved_view`，动态 / 固化双模式）

**概念**：保存筛选条件或成员快照形成的**引用视图**，数据引用原任务（非副本），视图内状态变更直接 UPDATE 原 `b04_task`（单一真实来源）。

| 模式 | 取值 | 行为 |
| --- | --- | --- |
| 动态引用 | `dynamic` | 运行时按 `filter_config`（含 `tag_ids`/`tag_match` 维度）实时计算命中任务；原任务改标签/状态会移出或加入 |
| 固化台账 | `fixed` | 保存时（或移除/补充触发时）将任务 ID 集合锁定进 `b04_saved_view_member`，成员固定；状态变更仍回写原任务 |

**能力清单**：

1. **两种创建方式并存**（台账需求 D3）：
   - 方式 A「保存为台账」：任务列表设置筛选 → 保存，默认 `dynamic`；
   - 方式 B「勾选创建」：任务列表勾选若干任务 → 创建，强制 `fixed`，成员 = 勾选的 ID 集合（不依赖筛选快照）；
2. **台账详情页**（`SavedViewList`）：
   - 复用任务列表筛选栏（`TaskFilterBar`：关键词/工作流/Owner/三状态/标签 AND·OR）；
   - **搜索叠加**：动态台账 = `filter_config` 基础筛选 **∩** 搜索条件；固化台账 = 成员内过滤（不增删成员）；
   - 表格列与操作对齐任务列表：状态流转、详情/备注、移除任务、批量操作（批量状态流转 + 批量打标签）、导出；
3. **移除转固化**（R4）：从任意台账移除任务（单条/批量）→ 无论原模式均转 `fixed`，剩余成员持久化锁定；动态台账「移除」即「快照固化」（当前命中集 − 被移除项为初始成员）；不可逆（删除重建除外）；移除仅解除成员关系，**不删除原任务**；
4. **固化台账补充任务**（§9 补充需求）：
   - 台账详情页「补充任务」→ 跳转任务列表并携带上下文 `?addToView=<viewId>&scenarioId=<scenarioId>`，任务页顶部显示上下文横幅；
   - 任务页搜索勾选 → 「添加到台账（N）」→ 对话框列出当前场景全部台账（标注模式与任务数），带上下文则预选锁定目标；
   - 加入成功：带上下文则**自动返回原台账详情页**；否则停留任务页提示成功；
   - 动态台账被补充时**自动固化**（与原命中集 + 新加入任务为成员）；加入幂等（重复加入不产生重复成员）；
5. **编辑 / 删除**：编辑名称/描述/筛选/模式（动态↔固化切换由后端重建/清空成员）；删除仅删视图与成员记录，不删任务；
6. **成员源删除**：原任务被逻辑删除后，固化台账仍展示该成员并标记「源已删除」，状态不可再变更。

#### 5.3.4 任务台账清单（`LedgerList`，R1）

- 任务迁移模块内独立「任务台账」列表页（按当前场景汇总全部台账）；
- 表格列：台账名称、描述、模式标签（动态引用/固化台账）、任务数（动态按 `filter_config` 计、固化按成员表计）、创建人、创建时间；
- 操作：打开（进详情）、编辑（名称/描述/模式）、删除；
- 场景栏 `ScenarioBar` 现有内联链接可保留为快捷入口，权威列表统一收敛到该页。

#### 5.3.5 标签管理与标签化台账（概念 `b06`）

> 来源：《任务迁移-标签管理与标签化台账需求》V1.1。标签严格**空间级**（存空间库 `b04_tag`），UI 为空间内**独立一级菜单**（概念对应 `CODEBUDDY.md` §3.2 预留 `b06_`），但**不新建 `b06` 表/库**，后端 API 归入 `b04` 服务（D9）。

1. **标签 CRUD**：标签 ID（系统生成展示）、名称（空间内唯一）、描述（选填）、分类（`manage` 管理标签 / `tech` 技术标签，**默认 tech**）、颜色（hex，预设调色板，默认 `#1a73e8`）；L0/L1/L2 均可维护；删除需二次确认，**级联解除关联但不删任务**；
2. **任务打标签**（多对多，经 `b04_task_tag`，唯一约束 `(task_id, tag_id)`，幂等）：
   - 单任务：详情/行内多选赋值与去标；
   - **内联 + 号打标**：任务表格「标签」列末尾 `+` 图标 → 弹出**已创建标签**多选浮层（按分类分组），选中即就地打标；浮层内**不可新建**（新建统一在标签管理模块）；点击已有标签 `×` 就地去标；
   - 批量打标签 / 批量去标签：列表多选 → 批量赋予/移除指定标签；
3. **按标签筛选**：筛选栏标签多选 + 「全部（AND，默认）/ 任一（OR）」切换；AND 语义 = 任务须**同时拥有所有**选中标签；可与其他条件组合；筛选结果可导出、可保存为台账；
4. **缺陷修复**：
   - F1：修复「含全部标签（AND）」筛选无结果的后端查询缺陷（`IN` + `HAVING COUNT(DISTINCT tag_id) = N`）；
   - F2：标签增/删/改后，标签列表与任务表格「标签」列**实时刷新**，无需手动刷新页面；
5. **数据模型**（空间库）：
   - `b04_tag`：标签主表（唯一约束 `(space_id, tag_name)`）；
   - `b04_task_tag`：任务-标签关联表；
   - `b04_saved_view` 增量：`view_mode`（`dynamic`/`fixed`，默认 `dynamic`）、`filter_config` 新增 `tag_ids`/`tag_match` 维度；
   - `b04_saved_view_member`：固化台账成员表（唯一约束 `(view_id, task_id)`，动态模式不写）；
6. **标签视觉**：色块 + 文字胶囊，圆角 `10px`、字号 `11px`（`CODEBUDDY.md` §6.4.2）。

#### 5.3.8 任务列表标签列折叠展示（来源：任务迁移-任务列表标签折叠需求 V1.0）

> 详细设计、交互与决策见碎片文档《任务迁移-任务列表标签折叠需求》V1.0。本小节仅做整合视图。纯前端展示优化，无后端 / 库表变更（任务列表接口已返回 `tags[]`）。

### 5.4 血缘管理（b07）

> 来源：《血缘管理-数据血缘需求》V2.0。**功能与交互全部直接复刻参考实现 `tools/hrwx_lineage`**（数据校验部分除外），按项目规范重构。

#### 5.4.1 定位与范围

- 以「迁移空间」为隔离单元，提供数据血缘的**检索驱动可视化查询**、**检索下钻**、**节点/边详情**与**按工作流解析脚本新增/重建**能力；

#### 5.4.2 核心决策（D1~D6）

| 编号 | 决策点 | 结论 |
| --- | --- | --- |
| D1 | 数据归属 | 空间库隔离：`b07_lineage` 置于 `mig_<space>_db` |
| D2 | 脚本解析 | 包含：粘贴/上传 SQL、PySpark，后端解析抽取血缘边并预览（移植参考 `lineage_parser`） |

#### 5.4.3 功能设计（R1~R5）

**R1 血缘可视化查询（检索驱动，复刻参考）**

- 进入即请求全量血缘边（`GET /lineages`），前端 `buildGraph` 构建邻接索引；画布初始为空态提示「请输入表名进行血缘检索」；
- 检索选中表 → 成为「当前表（聚焦表）」根节点，左→右分层 DAG 展示上游（左）/下游（右）；
- 节点着色：正式表 = 蓝填充 `#e8f0fe` / 描边 `#1a73e8`；临时表 = 琥珀橙填充 `#fef7e0` / 描边 `#f2a100`；当前聚焦表 = 绿色描边 `#188038`；圆角矩形，显示「库名 + 表名」两行（超长省略，hover 显全名）；
- **节点展开/收起特效（对齐参考）**：节点左（上游）/右（下游）各一个 `+/−` 圆形按钮 + **邻居数量角标**，点击展开/收起该方向一度；仅「可达方向」显示按钮（检索入口双向、上游到达只能继续向上、下游到达只能继续向下）；右键菜单：查看详情 / 展开上游全部 / 收起上游 / 展开下游全部 / 收起下游；

- 画布交互：缩放（`+/−` 与滚轮，0.2–2.5）、适应屏幕、重置视图、拖拽平移、PNG 导出（SVG→Canvas，底色 `#eef2f7`）；

- 图例：仅颜色图例，**无任何开关**（D6）。

**R2 血缘检索（感应提示）**

- 顶部检索栏直接复刻参考 `SearchBar`：输入即出下拉建议——**正式表名**（短名+全名+类型徽标+项目标签+任务类型标签）与**工作流名**（⚙ 图标+涉及表数+入口表）；支持 ↑/↓ 导航、回车确认、点击选择；

- 临时表按所属「工作流 + 脚本」上下文展开（不串到其他工作流）。

**R3 节点 / 边详情**

- 节点详情面板（右侧浮层）：表全名 + 选项卡「写入任务 / 读取任务」；每条任务展示任务名、项目、任务类型、脚本（可复制）、对侧表名（顿号分隔）；按工作流分组、默认折叠、点击展开；

**R4 血缘新增（按工作流解析脚本入库）**

- 「工作流管理」→「新增工作流血缘」→ `WorkflowDialog`：录入工作流名称（必填）、任务名、任务类型、项目名、脚本路径/名称；

**R5 血缘重建（按工作流覆盖）**

### 5.5 skill 管理（b08，平台级全局）

> 来源：《skill管理-skill市场与上传下载需求》V1.0。**平台级全局能力，不与迁移空间隔离绑定**（D1）。

#### 5.5.1 定位与范围
- 面向所有登录用户（L0/L1/L2）的 skill 市场：平铺展示公开 skill，支持手工上传（公开/私有）、web 下载与 REST API 上传/下载；
- 为后续「skill 人机对话方式」自动上传/下载预留并完整实现 REST API，采用 ak/sk 密钥 HMAC 签名鉴权；
- 用户 ak/sk 密钥在「个人中心 → API 密钥」自助管理（D2），与「用户管理仅 L0」规则解耦；
- skill 文件当前存服务器本地目录，存储层抽象以便后续对接对象存储（D5）。

#### 5.5.2 功能设计（SK-01~SK-07）
- **SK-01 市场展示**：全局菜单「skill 市场」卡片网格，字段含名称 / 简介（>60 字截断）/ 使用热度（下载次数）/ 公开·私有标签；支持搜索与排序（热度 / 最新）。
- **SK-02 手工上传**：任意登录用户上传 zip，填名称（平台级唯一）、简介、是否公开；文件落盘，作者 = 当前用户。
- **SK-03 私有可见性**：私有 skill 不进市场公开列表，仅上传者本人与 L0 可见 / 可下载（D4）；上传者可下架（仍可由本人管理）。
- **SK-04 web 下载**：公开 → 全员；私有 → 上传者 + L0；成功计数 +1。
- **SK-05 ak/sk 自管理**：个人中心生成 / 列表 / 停用 / 吊销自身密钥，secret 仅生成时展示一次。
- **SK-06 REST API**：`POST /b08/skills/upload`、`GET /b08/skills/{skill_code}/download`、`GET /b08/skills`；HMAC-SHA256 签名鉴权（头 `X-Access-Key`/`X-Timestamp`/`X-Nonce`/`X-Signature`，时间戳偏差 ≤5 分钟、nonce 5 分钟内不重复）。
- **SK-07 存储**：`SKILL_STORAGE_DIR` 本地目录，按 `skill_code/version.zip` 组织；`StorageBackend` 抽象，后续可换对象存储。

#### 5.5.3 数据模型（公共库，详见 §6.1）
- `b08_skill`：skill 主表（`skill_code` 平台级唯一、`name` 唯一、`is_public`、`status` 上架/下架、`download_count`、文件元数据、逻辑删除）；
- `common_user_api_key`：用户 API 密钥（`access_key` 明文、`secret_key_enc` 加密存储、状态、最近使用时间）。

### 5.6 数据校验管理（b05）

> 来源：《数据校验-数据校验结果导入与刷新需求》V1.0（D1~D8 交互确认）。本期同时落地三项体验优化：空间左侧菜单收起/展开（`LAYOUT-01`）、任务迁移查询页隐藏「任务URI」（`B04-05`）、`b04_task` 新增「数据校验结果」字段（`B04-06`）。

#### 5.6.1 数据校验列表（`B05-01`）
- **数据范围（D2）**：跟随 b03 迁移场景（空间头场景切换器在校验页激活，切换 b03 场景）；列表行 = 当前场景 `b03_table_item` 全部库表（逻辑未删）；
- **列**：源库表 / 目标库表 / 表类型 + **最新校验结果** + **近7天校验结果** 两列；
- **最新校验结果**：取该目标端库表 `data_date` 最大的一条记录（含今天），码值 `通过`=绿 `#27ae60`、`不通过`=红 `#e74c3c`，无记录展示「—」；
- **近7天校验结果（D8）**：不含今天的前 7 个自然日（T-7~T-1），左→右日期降序（最近在左）；7 个圆角 `4px` 小方块：通过=绿实心、不通过=红实心、无记录=灰空心；hover 提示「`MM-DD 通过｜源端 12,345 / 目标端 12,345`」。

#### 5.6.2 校验结果导入（`B05-02`）
- **导入对话框**：模版下拉（默认模版 / 腾讯数据校验工具模版）→ 校验结果所属日期（默认今天，不可晚于今天）→ 文件上传（`.xls / .csv / .xlsx`，复用 `read_tabular` 三格式读取）→ 模版列说明联动 → 下载导入模版；
- **默认模版**：库名 / 表名 / 源端数据量 / 目标端数据量 / 结果(通过/不通过)，表头名映射、列序不敏感；
- **腾讯数据校验工具模版**：直接消费 TDM 导出 CSV（`srcDatabase/srcTable/srcResult/dstResult/checkResult`），转换逻辑参考 `convert_check_result.py`（`checkResult=true` 大小写不敏感→通过，其余→不通过），免去线下转换；
- **日期与覆盖（D5）**：`data_date` 批量写入本次导入全部记录；同「数据日期+库名+表名」按唯一键 upsert 覆盖，文件内重复行以最后一行为准；
- **清单外库表（D6）**：正常入库并照常参与任务刷新，导入结果提示条数，校验列表页不展示。

#### 5.6.3 导入后自动刷新任务数据校验结果（`B05-03`）
- **触发**：导入接口内、结果入库提交后同步执行，返回 `refreshed_tasks`；
- **关联链路（D3，目标端口径）**：`b05_check_result` 库名.表名 → `b07_lineage.output_table`（`output_table_type='正式表'`）取 `project_name + task_name` → `b04_task`（同键关联）；
- **判定（D7）**：任务全部正式输出表中，有记录的全为通过→`通过`；任一不通过→`不通过`；均无记录→`无校验结果`；每张输出表独立取全历史最新记录（增量范围：仅本次导入涉及库表命中的任务）。

#### 5.6.4 布局与 b04 配套优化
- **LAYOUT-01**：项目空间左侧分组菜单支持收起/展开（D4：收起后完全隐藏、左缘留展开按钮、右边面板自适应、`localStorage` 持久化）；
- **B04-05**：任务列表 / 台账详情任务列移除 `task_uri` 展示（详情抽屉保留；字段与唯一约束不动）；
- **B04-06**：`b04_task` 新增 `check_result VARCHAR(32) NOT NULL DEFAULT '无校验结果'`（与手工维护的 `check_status` 并存不互相覆盖，D1）；模板必选（锁定必填扩为 9 项）、列表展示默认「否」；导入允许留空落「无校验结果」、非法码值行报错；详情只读展示；存量空间模板启动时自动补齐该字段。

## 8. 安全与质量约束

1. **密码安全**：bcrypt/argon2 哈希存储；禁止明文落库与日志打印；密码复杂度 ≥8 位含三类字符；
2. **Markdown 防 XSS**：查看态渲染必须经 DOMPurify（或等价净化库）净化后注入，禁止直接 `v-html` 原始内容；
3. **下载安全**：`.md` 文件名净化（去路径分隔符/控制字符、限长），防头注入与路径穿越；
4. **空间隔离**：所有空间内数据带 `space_id`，查询与写入强制按当前空间过滤，禁止跨空间访问；
5. **删除安全**：删除标签级联解关联不删任务；删除台账仅删视图与成员不删任务；用户注销为停用不删数据；
6. **单一真实来源**：台账视图内状态变更直接 UPDATE `b04_task`，台账不存任务副本；
7. **审计**：状态流转、删除、密码变更、标签增删改、打/去标、同步类操作记录操作人与变更前后；
8. **导入安全**：Excel/CSV 导入校验文件类型与大小上限，解析失败给出行级错误提示；
9. **分层与响应**：router → service → repository → model 分层，跨层 Pydantic Schema 传递，禁止直接返回 ORM 对象；统一响应信封；
10. **视觉一致**：前端严格遵循 `CODEBUDDY.md` §6.4 设计令牌（主题色板 / 语义配色 / 圆角间距阴影 / z-index 梯度），不引入第二套配色。

## 10. 范围边界与迭代规划

### 10.1 本期范围（P0/P1）
