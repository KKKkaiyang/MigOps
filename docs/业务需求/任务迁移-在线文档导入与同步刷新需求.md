# 迁移管家（MigOps）任务迁移 — 在线文档导入与同步刷新需求

> 文档版本：V1.0 ｜ 编写日期：2026-10-22 ｜ 状态：**已作废**（2026-10-23 经确认本需求暂不推进，内容保留仅供追溯）
> 适用范围：任务迁移管理（`b04`）的任务台账导入能力增强——在既有 Excel/CSV 离线导入基础上，新增**腾讯文档在线表格**导入与**手动同步刷新**能力
> 配套文档：`docs/业务需求/项目空间业务功能需求.md`（下称"上位需求"，本需求扩展其 §6 `b04` 导入能力）、`docs/业务需求/迁移管家平台-业务需求文档.html`（平台总 BRD）、根目录 `CODEBUDDY.md`（开发规范）

> ⚠️ **本需求已作废**：2026-10-23 经确认，在线文档导入与同步刷新需求暂不推进，相关腾讯文档导入、手动同步刷新等功能均不在本期实现范围。若后续重新启动，请以最新版需求文档为准。

## 1. 概述

### 1.1 背景与目标
任务迁移台账当前仅支持 Excel/CSV 离线导入（覆盖 / 增量两种模式，见上位需求 §6.2.2）。实际项目中，迁移团队常使用**腾讯文档在线表格**多人协同维护任务清单，并希望平台台账能与在线文档保持一致、减少重复录入。

本需求在 `b04` 导入能力上做整体增强：

- **双来源导入**：任务台账支持两种导入来源——① 线下 Excel/CSV 文档（既有能力保留）；② 腾讯文档在线表格（新增）；
- **在线同步刷新**：对来自在线文档的台账，支持从在线文档**手动同步刷新**内容，保持平台台账与在线文档一致；
- **字段级可控**：同步时按列指定「来源」，在线文档只更新其负责的列，平台维护的状态列与备注不被误覆盖；
- **安全接入**：通过腾讯文档开放平台 OAuth 授权接入，凭证加密存储，按用户归属。

### 1.2 范围
| 模块 | 归属 | 本期范围 |
| --- | --- | --- |
| 任务台账导入来源扩展 | `b04` | 新增「腾讯文档在线表格」导入来源，与既有 Excel 离线导入并存 |
| 在线文档绑定与授权 | `b04` | 场景内绑定在线文档、OAuth 授权、凭证管理 |
| 字段来源配置 | `b04` | 每个绑定文档单独配置各列来源（online / platform） |
| 手动同步刷新 | `b04` | 从在线文档手动触发同步，按字段来源更新台账 |
| 同步历史与报告 | `b04` | 记录每次同步的变更统计与行级错误 |

**不在本期范围**：

- 双向写回（平台改动写回在线文档）：本期仅 **online → platform 单向**同步，「双向」列作为预留，见 §8 默认项；
- 定时自动同步：本期仅手动触发，见 §8 决策 D3；
- `b03` 数据迁移清单的在线文档导入：本期仅 `b04`，模式可后续复用于 `b03`；
- 在线文档的「标签列 / 标签筛选」：延续上位需求，标签能力整体二期。

### 1.3 术语
| 术语 | 含义 |
| --- | --- |
| 导入来源 | 任务台账数据的两个来源：线下 Excel/CSV 文档、腾讯文档在线表格 |
| 在线文档绑定 | 在任务迁移场景下登记的一个腾讯文档在线表格（含链接、授权、字段来源配置），作为同步的数据源 |
| 字段来源 | 每个 `b04_task` 列在同步时的归属：`online`（以在线文档为准，可被覆盖）/ `platform`（仅平台维护，同步跳过） |
| 手动同步 | 用户在场景内点击「同步」按钮，触发从绑定在线文档拉取并应用变更 |
| 智能保留 | 在线文档删除某行时，对平台已产生作业成果（状态非初始 / 有备注）的任务行保留并标记，纯导入行则删除 |

## 2. 总体设计

```
任务迁移场景（b04_scenario）
  ├─ 导入来源切换
  │    ├─ 线下 Excel/CSV 导入（既有：覆盖 / 增量，模板下载）
  │    └─ 腾讯文档在线表格
  │         ├─ 绑定在线文档（可多个）── b04_doc_binding
  │         │    ├─ OAuth 授权（用户级，token 加密存储）
  │         │    └─ 字段来源配置（每列 online/platform）
  │         └─ 手动「同步」按钮 ──→ 拉取在线表格 ──→ 按字段来源应用 ──→ b04_sync_log
  └─ 任务台账（b04_task，含 source_type / source_doc_id / 同步标记）
```

- **来源并存**：同一场景可同时拥有「离线 Excel 导入的行」与「多个在线文档绑定的行」，通过 `b04_task.source_type` 与 `source_doc_id` 区分；
- **同步方向**：本期严格单向（online → platform）；
- **Upsert 键**：复用既有唯一约束 `(scenario_id, task_uri)`，以 `项目名称://任务名称@工作流名称` 匹配在线行与平台行，避免重复建行；
- **删除隔离**：智能保留仅作用于「该绑定文档供给的 online 行」，不会误删离线导入或其他绑定文档的行。

## 3. 功能要点

### 3.1 导入来源切换
- 任务台账导入入口升级为「导入 / 同步」面板，提供来源切换：**线下 Excel/CSV** 与 **腾讯文档在线表格**；
- 线下来源沿用既有能力：覆盖导入 / 增量导入两种模式、模板下载、行级错误提示（上位需求 §6.2.2），本期不改动其行为；
- 在线来源为本需求新增，详见 §3.2~§3.6。

### 3.2 在线文档绑定与 OAuth 授权
1. 用户在场景内「绑定在线文档」，粘贴腾讯文档链接（docs.qq.com 在线表格），系统解析出文档唯一标识；
2. **OAuth 授权**：平台已注册腾讯文档开放应用，用户首次同步时跳腾讯文档 OAuth 授权自己的账号；授权后 `access_token` / `refresh_token` 按用户**加密存储**（AES），禁止明文落库与日志打印；
3. 绑定记录登记文档名称、链接、授权用户（`owner_user_id`）、授权状态（`authorized` / `expired` / `unauthorized`）；
4. **凭证失效**：`access_token` 过期用 `refresh_token` 静默刷新；`refresh_token` 失效 / 用户解除授权 → 绑定置 `expired`，下次同步引导用户重新授权；
5. 一个场景可绑定**多个**在线文档（多文档同步时合并入同一台账）。

### 3.3 字段来源配置（字段级可配置）
- 每个绑定文档单独持有一份**字段来源配置**（per-doc，JSON），列出 `b04_task` 各列的来源 `online` / `platform`；
- 提供**默认映射**（用户可在同步设置中逐列修改）：

| 列 | 默认来源 | 说明 |
| --- | --- | --- |
| `workflow_name` 工作流名称 | online | 在线文档供给 |
| `task_name` 任务名称 | online | 在线文档供给（参与 task_uri 生成） |
| `script_name` 脚本名称 | online | 在线文档供给 |
| `owner` 任务 Owner | online | 在线文档供给 |
| `input_tables` 输入表 | online | 在线文档供给 |
| `output_tables` 输出表 | online | 在线文档供给 |
| `migration_status` 迁移状态 | platform | 仅平台维护，同步跳过 |
| `schedule_status` 调度状态 | platform | 仅平台维护，同步跳过 |
| `check_status` 数据校验状态 | platform | 仅平台维护，同步跳过 |
| `latest_note` 最新备注摘要 | platform | 仅平台维护，同步跳过 |
| 排查备注（`b04_task_note`） | platform | 在线文档不供给，始终平台维护 |

- 「双向」来源本期作为预留项（配置可存但行为等同 platform，不写回在线文档，见 §8 默认项）。

### 3.4 手动同步刷新
- 用户对每个已绑定文档点击「同步」（或在场景级「同步全部」批量触发所有绑定）；
- 同步流程：
  1. 以绑定授权用户的 OAuth 凭证调用腾讯文档开放 API 拉取在线表格内容；
  2. 按既有 Excel 模板字段解析为行（字段校验、类型 / 大小上限同既有导入安全策略）；
  3. 对每行以 `task_uri` 为键 **upsert**：
     - 新行：插入，`source_type='online'`、`source_doc_id=绑定.id`；
     - 已存在行：按字段来源配置更新——`online` 列覆盖，`platform` 列跳过（保留平台值）；
  4. **智能保留**（§3.5）处理在线已删行；
  5. 生成同步历史记录，更新绑定最近同步时间 / 状态 / 统计；
  6. 行级解析 / 写入错误计入统计，**不阻断整体**（部分成功）。

### 3.5 删除与智能保留
- 拉取结果集合记为该绑定「在线当前存在集」；
- 对 `source_doc_id = 该绑定.id` 且 `source_type='online'` 的平台已有行，若不在在线存在集：
  - **平台已维护**（迁移 / 调度 / 校验状态非初始值，或存在排查备注）→ 逻辑保留，置 `source_deleted_flag=1`，列表提示「源已删除」，状态不变；
  - **纯导入未改动**（状态均为初始、无备注）→ 逻辑删除（`deleted_at`），与离线导入删除一致；
- 仅作用于本绑定供给的 online 行，不影响离线导入或其他绑定文档行。

### 3.6 同步历史与报告
- 每次同步写入 `b04_sync_log`：触发人、触发方式（本期仅 `manual`）、起止时间、状态（成功 / 部分成功 / 失败）、变更统计（新增 / 更新 / 删除 / 跳过 / 错误数）、行级错误明细；
- 绑定列表与同步面板可查看最近同步时间、状态与统计摘要，点击展开历史。

## 4. 数据模型（空间库 `mig_<space_code>_db`）

### 4.1 `b04_task` 增量字段
| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `source_type` | VARCHAR(16) | 非空，默认 `offline` | 数据来源：`offline`（线下 Excel/CSV）/ `online`（腾讯文档在线表格） |
| `source_doc_id` | BIGINT | 可空 | 关联 `b04_doc_binding.id`；`offline` 为 NULL |
| `last_sync_at` | DATETIME | 可空 | 最近一次从该在线文档同步的时间 |
| `source_deleted_flag` | TINYINT | 默认 0 | 在线源行已删除标记（智能保留场景，1=源已删，平台保留） |

> 既有唯一约束 `(scenario_id, task_uri)` 不变，作为在线同步 upsert 键。

### 4.2 在线文档绑定表（`b04_doc_binding`）
| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK，自增 | 主键 |
| `space_id` / `scenario_id` | BIGINT | 非空 | 所属空间 / 任务迁移场景 |
| `doc_name` | VARCHAR(255) | 非空 | 文档名称（展示用） |
| `doc_url` | VARCHAR(1024) | 非空 | 腾讯文档链接 |
| `doc_id` | VARCHAR(255) | 非空 | 腾讯文档唯一标识（由链接解析 / API 返回） |
| `owner_user_id` | BIGINT | 非空 | 授权用户（以其 OAuth 凭证拉取） |
| `auth_status` | VARCHAR(32) | 非空，默认 `unauthorized` | `authorized` / `expired` / `unauthorized` |
| `field_mapping` | JSON | 非空 | 字段来源配置（每列 `online` / `platform`，默认映射见 §3.3） |
| `last_sync_at` | DATETIME | 可空 | 最近同步时间 |
| `last_sync_status` | VARCHAR(32) | 可空 | `success` / `partial` / `failed` |
| `last_sync_summary` | JSON | 可空 | 最近同步统计 `{added, updated, deleted, skipped, errors}` |
| 审计字段 | — | 必填 | `created_by` / `created_at` / `updated_by` / `updated_at` / `deleted_at` |

### 4.3 同步历史表（`b04_sync_log`）
| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK，自增 | 主键 |
| `space_id` / `scenario_id` / `binding_id` | BIGINT | 非空 | 所属空间 / 场景 / 绑定文档 |
| `triggered_by` | BIGINT | 非空 | 触发用户 |
| `trigger_type` | VARCHAR(16) | 非空，默认 `manual` | 本期仅 `manual` |
| `started_at` / `finished_at` | DATETIME | 可空 | 起 / 止时间 |
| `status` | VARCHAR(32) | 非空 | `success` / `partial` / `failed` |
| `summary` | JSON | 可空 | `{total, added, updated, deleted, skipped, errors}` |
| `error_detail` | JSON | 可空 | 行级错误明细（行号、列、原因） |
| 审计字段 | — | 必填 | `created_by` / `created_at` / `updated_by` / `updated_at` |

### 4.4 用户腾讯文档凭证表（加密存储）
| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | PK，自增 | 主键 |
| `user_id` | BIGINT | 非空，唯一（按用户） | 授权用户 |
| `access_token` | VARCHAR(512) | 非空 | 加密存储（AES） |
| `refresh_token` | VARCHAR(512) | 可空 | 加密存储（AES） |
| `expires_at` | DATETIME | 可空 | `access_token` 过期时间 |
| 审计字段 | — | 必填 | `created_at` / `updated_at` |

> 凭证按用户归属（与绑定 `owner_user_id` 对应）；存储位置默认置于公共业务库 `mig_common_db`（用户级、跨空间复用），具体落库以实现评审为准（见 §8 默认项）。

## 5. 接口与交互概要
- 既有 Excel 导入接口保持不变；
- 新增（均置于 `/api/v1/b04` 路由分组）：
  - 在线文档绑定：`POST /scenarios/{id}/doc-bindings`、`GET`、`PATCH`（字段来源 / 名称）、`DELETE`、`POST /{bindingId}/authorize`（OAuth 引导）、`POST /{bindingId}/sync`（手动同步）、`POST /scenarios/{id}/sync-all`；
  - 同步历史：`GET /scenarios/{id}/sync-logs`；
  - `b04_task` 列表响应补充 `source_type`、`source_deleted_flag` 供前端展示来源标记。
- 统一响应结构 `{ code, message, data, trace_id }`，遵循 `CODEBUDDY.md` §5.3。

## 6. 安全与质量约束
1. **凭证安全**：OAuth `access_token` / `refresh_token` 仅存 AES 加密密文，禁止明文落库与日志打印（复用 `app/core/security`）；
2. **授权边界**：仅绑定 `owner_user_id` 对应授权用户的凭证可拉取该文档；用户解除授权 / token 失效须引导重授权，不得越权读取他人文档；
3. **导入安全**：在线文档解析沿用既有 Excel 导入安全策略（文件 / 内容类型与大小校验、行级错误提示），解析失败给出明确行级错误；
4. **操作留痕**：绑定增删改、手动同步均记录操作人与时间；同步写入 `b04_sync_log`；
5. **分层与响应**：router → service → repository → model 分层，跨层 Pydantic Schema 传递；
6. **失败不污染**：行级错误计入同步统计但不阻断整体，避免单条脏数据导致全量失败。

### 8.2 默认处理（评审确认）
| 编号 | 议题 | 默认处理 |
| --- | --- | --- |
| A1 | Upsert 键 | 复用既有 `(scenario_id, task_uri)` 唯一约束，以任务 URI 匹配在线行与平台行 |
| A2 | 模板一致性 | 在线文档与 Excel 导入共用同一字段模板（字段、列序可对齐） |
| A3 | 权限模型 | 绑定 / 同步为业务操作，L0/L1/L2 均可（沿用上位需求 §2.2）；OAuth 授权为个人行为，绑定登记 `owner_user_id` |
| A4 | 凭证存储位置 | 用户级凭证表默认置于 `mig_common_db`（跨空间复用），具体以实现评审为准 |
| A5 | 「双向」列行为 | 配置可存 `bidirectional`，本期等同 `platform`，不写回在线文档 |
| A6 | 多文档同步顺序 | 「同步全部」按绑定创建顺序依次同步，各自独立记录历史 |
| A7 | 失败处理 | 行级错误跳过并计数，整体不回滚；状态置 `partial` / `failed`（有严重错误时） |
| A8 | 状态默认 | 在线同步进入的行初始状态沿用既有默认值（迁移状态「未开始」等） |
