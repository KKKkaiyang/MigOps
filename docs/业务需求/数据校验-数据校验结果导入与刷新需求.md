## 1. 概述

### 1.1 背景与目标
数据校验是迁移全流程（需求调研 → 元数据/数据迁移 → 任务迁移 → 数据校验 → 客户验收）中「输出表数据对齐」的确认环节。当前平台 `b05` 数据校验管理仅有占位（路由桩），校验结果散落在现场执行的腾讯数据校验工具（TDM）导出文件中，存在四个断点：

1. **校验结果无线上载体**：TDM 校验结果只能线下传文件，平台无法按日期沉淀、无法按库表追溯近 7 天校验走势；
2. **任务维度无自动结论**：任务迁移基础表无法体现「该任务全部输出表是否校验通过」，需人工翻文件核对；
3. **查询页信息噪音**：任务迁移查询页任务列下方展示技术型「任务URI」，对业务用户无意义；
4. **空间内导航不可收起**：左侧分组菜单固定 208px，库表列较宽的页面（如数据校验列表）可视区域被压缩。

本期以「数据校验结果导入」为入口，打通 **TDM 校验文件 → 平台沉淀 → 库表级校验视图 → 任务级校验结论自动刷新** 的闭环，并顺带完成上述 3、4 两项体验优化。

### 1.2 范围
| 能力 | 归属 | 本期范围 |
| --- | --- | --- |
| 左侧菜单收起/展开 | 空间视图框架 | 项目空间侧边分组导航支持收起（完全隐藏+展开按钮）与展开，右边面板自适应，状态持久化 |
| 查询页隐藏任务URI | `b04` | 任务列表/筛选/导出不暴露 `task_uri`；详情抽屉保留 |
| 基础表新增数据校验结果 | `b04` | `b04_task` 新增 `check_result` 独立字段；模板必选、列表展示默认关 |
| 数据校验列表页 | `b05` | 以 b03 库表清单为行，追加「最新校验结果」「近7天校验结果」两列 |
| 数据校验结果导入 | `b05` | 双模版（默认/腾讯工具）、三种格式、校验结果所属日期、upsert 覆盖 |
| 导入后自动刷新 | `b05` → `b04` | 按血缘输出正式表关联，刷新任务级 `check_result` |

**不在本期范围**：
- 血缘图（b07）的校验状态叠加与校验浮层（b05 供数、b07 消费，二期）；
- 校验规则管理、校验问题排查/整改跟踪（`b05` 其它能力，二期）；
- 数据校验结果的手工逐条录入/编辑（本期仅导入入口）；
- `b05` 的 ak/sk 接口开放（二期，与平台 ak/sk 规划一致）；
- 客户验收模块。

### 1.3 术语
| 术语 | 含义 |
| --- | --- |
| 目标端库表 | 本需求中校验结果「库名.表名」的统一口径，对应 `b03_table_item.target_db_name.target_table_name`（目标库名.目标表名）与 `b07_lineage.output_table`（血缘输出表） |
| 数据校验结果（`check_result`） | `b04_task` 新增字段，码值 `通过 / 不通过 / 无校验结果`，由校验结果导入后**系统自动刷新**，不手工维护 |
| 数据校验状态（`check_status`） | 既有字段，码值 `校验通过 / 校验不通过 / 微小差距`，手工维护；与 `check_result` **并存不互相覆盖**（D1） |
| 校验结果所属日期 | 导入时前端选择的数据日期（`data_date`），批量写入本次导入的全部记录 |
| 最新校验结果 | 某目标端库表在 `b05_check_result` 中 `data_date` 最大的一条记录的结果 |
| 近7天校验结果 | **不含今天**的前 7 个自然日（T-7 ~ T-1，以今天为 T）的校验结果序列 |
| 默认模版 | 平台导入模版：库名、表名、源端数据量、目标端数据量、结果(通过/不通过) |
| 腾讯数据校验工具模版 | 直接消费 TDM 校验结果 CSV（`srcDatabase/srcTable/srcResult/dstResult/checkResult`），转换逻辑参考 `convert_check_result.py` |

## 3. LAYOUT-01 — 左侧菜单收起与展开

### 3.1 功能描述
项目空间视图（`SpaceLayout`）的左侧分组导航支持**收起与展开**：展开态维持现有 208px 分组导航；收起态侧边栏**完全隐藏**，原位置留一个展开按钮，右边主面板自适应撑满。

### 3.2 交互规则（已确认 D4）
- **切换按钮**：
  - 展开态：侧边栏顶部右侧放置「« 收起」按钮（hover 提示「收起菜单」），点击后侧边栏隐藏；
  - 收起态：侧边栏**完全移除**（非图标模式），页面最左侧保留一个窄条（宽 28px）承载「» 展开菜单」按钮（hover 提示「展开菜单」），点击后侧边栏恢复。
- **收起态布局**：`.space-main`（`flex:1` + `min-width:0`）自动占满可用宽度，**无需改动各业务页面结构**。
- **状态持久化**：收起/展开状态写入 `localStorage`（键 `migops:space:sidebar-collapsed`），刷新页面、切换路由、切换空间后保持；默认展开。
- **范围**：仅项目空间内（`/space/:spaceId`）左侧菜单；全局顶栏（`App.vue`）不在本期范围。

### 3.3 与新增「数据校验」菜单项的关系
本期 `b05` 数据校验列表页新增侧边菜单项（见 §6.2），与既有菜单项遵循同一套收起/展开规则，无特殊处理。

### 3.4 前端变更要点
- `SpaceLayout.vue`：新增 `sidebarCollapsed` 状态（`ref` + `localStorage` 读写）、折叠/展开切换按钮；`v-if` 控制 `aside.sidebar` 与收起态窄条渲染；
- 侧边栏分组结构不变（空间概览 / 资料准备 / 迁移执行 / **数据校验（新增分组）** / 数据资产）；
- 空间头（`.space-head`）与场景切换器行为不变。

## 4. B04-05 — 任务迁移查询页隐藏「任务URI」

### 4.1 功能描述
任务迁移查询页（任务列表 `TaskMigrationList`）不再展示「任务URI」。URI（`project_name://task_name@workflow_name`）为技术定位标识，对业务用户无阅读价值，且与任务名称重复表达。

### 4.2 隐藏范围
| 位置 | 调整 |
| --- | --- |
| 任务列表「任务」列 | 仅展示任务名称（点击看详情），**移除任务名下方 mono 小字的 `task_uri` 展示**（当前 `TaskMigrationList.vue` 任务列第二行） |
| 台账详情页任务列 | 同样移除 `task_uri` 展示（当前 `SavedViewList.vue` 任务列第二行） |
| 筛选栏 | 不提供 `task_uri` 筛选条件（当前无，保持）；关键词搜索匹配范围不变 |
| 导出（任务台账.xlsx / 自定义台账.xlsx） | 导出列由空间模板字段驱动，不含 URI 列（保持） |

### 4.3 保留范围
- **任务详情抽屉**：保留 `task_uri` 展示（排查/定位用途，非查询页）；
- **字段本身**：`task_uri` 仍由导入自动生成，仍为 `(scenario_id, task_uri)` 唯一约束，**不删除、不改语义**；
- 台账（`SavedViewList`）等复用任务表格的页面，按任务列表同规则不展示 URI。

## 5. B04-06 — 基础表新增「数据校验结果」字段

### 5.1 功能描述
任务迁移基础表数据模型（`b04_task`）新增字段「**数据校验结果**」，码值：`通过 / 不通过 / 无校验结果`（默认 `无校验结果`）。该字段表达「该任务全部正式输出表的数据校验结论」，由 `b05` 校验结果导入后按 §8 规则**自动刷新**。

### 5.2 与既有「数据校验状态」的关系（已确认 D1）
| 维度 | 数据校验状态 `check_status`（既有） | 数据校验结果 `check_result`（新增） |
| --- | --- | --- |
| 码值 | 校验通过 / 校验不通过 / 微小差距（空=未校验） | 通过 / 不通过 / 无校验结果 |
| 维护方式 | 手工（行内/批量状态流转） | **系统自动刷新（只读）** |
| 数据来源 | 人工跟进结论 | `b05_check_result` + 血缘输出表聚合 |
| 模板必选 | 是（原 8 项锁定必填之一） | 是（扩为 9 项锁定必填之一） |

两字段**并存**，界面均展示、互不覆盖、互不同步。

### 5.3 数据模型变更（空间库）
- 表：`b04_task`；新增列 `check_result VARCHAR(32) NOT NULL DEFAULT '无校验结果'`，注释「数据校验结果:通过/不通过/无校验结果(b05校验结果导入后按血缘输出表刷新)」；
- DDL：空间库增量 DDL 幂等补齐（存量表 `ADD COLUMN`，新表由 `create_all` 建）；存量任务默认落 `无校验结果`。

### 5.4 配置字段模板变更
- `BASE_TEMPLATE_FIELDS` 增加 `("check_result", "数据校验结果", is_required=True, display_in_list=False)`，顺序位于基础字段末尾（`order=14`）；
- 锁定必填字段集合（`REQUIRED_TEMPLATE_FIELDS`）由 8 项扩为 **9 项**：`project_name / task_name / migration_owner / active_status / migration_status / dualrun_status / check_status / acceptance_status / check_result`——模板必须包含该字段且勾选「必选」；
- **列表显示默认：否**（`display_in_list=False`）：默认模板与存量空间模板升级后，该字段不出现在任务列表；用户可在「配置字段模板」中手动开启；
- 存量空间模板升级：空间模板拉取/初始化时，将 `check_result` 补入 `config_json.fields`（必选开、列表展示关、order 末尾），保留用户其它字段配置不变。

### 5.5 导入与维护行为
- **导入模板**：任务导入 Excel/CSV 增加「数据校验结果」列（模板下载自动包含）；
- **行数上限**：导入基础数据单文件上限 **50000 行**（b04 专用 `MAX_TASK_IMPORT_ROWS`，不影响 b03 的 5000 行；导入按预取已有任务 + 批量插入实现，前端请求超时相应放宽至 5 分钟）；
- **行级规则**：该列**允许留空**——留空落 `无校验结果`（「必选」仅约束模板必须包含该列，不强制行值非空，与其它必填字段的行级非空校验相区别）；填入时校验码值，非法值该行报错；
- **覆盖导入**：该列参与更新（会被 Excel 值覆盖）；
- **系统刷新优先**：`b05` 导入后的自动刷新（§8）会覆盖该列；因此任务详情页该字段**只读展示**，不提供手工编辑，批量状态流转不含该字段；
- **列表渲染**：开启后与其它字段同列渲染，码值着色：通过=绿 `#27ae60`、不通过=红 `#e74c3c`、无校验结果=灰 `#bdc3c7`（对齐 `CODEBUDDY.md` §6.4.2 校验语义色）。

## 6. B05-01 — 数据校验列表页

### 6.1 数据范围（已确认 D2）
跟随 **b03 数据迁移场景**：空间头场景切换器在数据校验页激活（切换的是 b03 场景，与数据迁移页一致，含场景创建/删除入口）；列表行 = 当前 b03 场景下 `b03_table_item` 全部库表（逻辑未删），左连 `b05_check_result`。未选择场景时展示空态「请先在空间头部选择或创建迁移场景」。

### 6.2 入口与路由
- 侧边菜单新增「**数据校验**」菜单项：独立分组，位于「迁移执行」与「数据资产」之间（对应业务流程中任务迁移之后的校验阶段；如后续增加客户验收可同构扩展）；
- 路由：`/space/:spaceId/data-checks`（`name: space-data-checks`，`module: 'b05'`）；
- 页面操作区：「导入校验结果」按钮 + 关键词筛选（源库名/源表名/目标库名/目标表名模糊）+ 分页。

### 6.3 列定义
| 列 | 来源 | 说明 |
| --- | --- | --- |
| 源库名 / 源表名 | `b03_table_item.db_name / table_name` | 默认展示 |
| 目标库名 / 目标表名 | `b03_table_item.target_db_name / target_table_name` | 默认展示；**校验结果关联主键口径** |
| 表类型 | `b03_table_item.table_type` | 默认展示 |
| **最新校验结果** | `b05_check_result` 聚合 | 见 §6.4 |
| **近7天校验结果** | `b05_check_result` 聚合 | 见 §6.5 |

> 清单其它列（迁移状态等）如需展示，沿用清单列显隐机制扩展，不影响两列校验列的固定末尾位置。
> **关联键容错**：清单行目标库表为空时，按源库表名回退关联（兼容未维护目标库表的老数据）。

### 6.4 最新校验结果
- 取该目标端库表（`b05_check_result.db_name.table_name` = `target_db_name.target_table_name`）中 `data_date` **最大**的一条记录，展示其 `result`；
- 码值标签：`通过`=绿 `#27ae60`、`不通过`=红 `#e74c3c`；
- 无任何记录：展示「—」（灰色弱化）；
- 该列取全历史最新（**含今天**导入的数据），与 §6.5 的近7天窗口相互独立。

### 6.5 近7天校验结果（已确认 D8）
- **窗口**：不含今天，往前 7 个自然日（**T-7 ~ T-1**，以今天为 T）；
- **排列**：从左到右日期**降序**（最左 = 昨天 T-1，最右 = T-7）——「最近在左」；
- **方格形态**：圆角 `4px` 小方块（约 14×14px，间距 4px），一行 7 个；
  - 当日有记录且 `通过`：**绿色实心** `#27ae60`；
  - 当日有记录且 `不通过`：**红色实心** `#e74c3c`；
  - 当日无记录：**灰色空心**（浅灰填充 + `#bdc3c7` 描边）；
- **悬浮提示（hover）**：「`MM-DD 通过｜源端 12,345 / 目标端 12,345`」；无记录日：「`MM-DD 无校验记录`」；数据量千分位展示；
- 后端返回的 `recent_days` 数组**按日期降序**（索引 0 = 昨天，索引 6 = 7 天前），与左→右展示顺序一致，前端直接顺序渲染。

### 6.6 后端接口
- `GET /b05/checks?space_id=&scenario_id=&keyword=&page=&page_size=` → 分页返回 `CheckOverviewOut[]`：
  - 行字段：`item_id / scenario_id / db_name / table_name / target_db_name / target_table_name / table_type`；
  - `latest_result / latest_date / latest_src_volume / latest_dst_volume`（无记录为 `null`，前端展示「—」）；
  - `recent_days: CheckResultDay[]`（长度 7，降序；每日含 `data_date / result / src_volume / dst_volume`，无记录 `result=null`）；
- 统一响应信封 `{code,message,data,trace_id}`，分页 `{list,total,page,page_size}`（沿用 `CODEBUDDY.md` §5.3）。

## 7. B05-02 — 数据校验结果导入

### 7.1 导入对话框
数据校验页点击「导入校验结果」弹出对话框，字段自上而下：

1. **导入模版**（下拉框，必选，默认「默认模版」）：`默认模版` / `腾讯数据校验工具模版`；下拉切换时联动下方列说明区；
2. **校验结果所属日期**（日期选择器，必选，默认今天，**不可晚于今天**）：批量写入本次导入全部记录；
3. **文件上传**（点击/拖拽）：支持 `.xls / .csv / .xlsx`；
4. **模版列说明区**：随模版切换展示列定义与字段映射（见 §7.2 / §7.3）；
5. **下载导入模版**：默认模版下载 xlsx（含表头+示例行）；腾讯模版下载字段说明与示例 CSV。

确认导入后一次性完成「解析 → 行校验 → 入库 → 任务级刷新（§8）」，返回结果摘要；错误行不阻塞其它行。

### 7.2 默认模版
| 列（表头名） | 必填 | 说明 |
| --- | --- | --- |
| 库名 | 是 | 目标端库名 |
| 表名 | 是 | 目标端表名 |
| 源端数据量 | 否 | 整数，兼容千分位与 Excel 数字单元格 |
| 目标端数据量 | 否 | 同上 |
| 结果 | 是 | 仅接受 `通过 / 不通过`，其它值该行报错 |

- 表头名称严格匹配，**列顺序不敏感**（按表头名映射）；
- 库名.表名 拼接后即「目标端库表全名」，为 §6 关联与 §8 刷新的唯一键口径。

### 7.3 腾讯数据校验工具模版
转换逻辑参考 [`convert_check_result.py`](../腾讯数据校验工具文件示例/convert_check_result.py)，平台**直接消费 TDM 校验结果 CSV**，不要求用户先执行脚本转换：

| TDM 字段 | 映射为 | 说明 |
| --- | --- | --- |
| `srcDatabase` | 库名 | 与默认模版同口径（目标端库表） |
| `srcTable` | 表名 | 与 `srcDatabase` 拼接为 库名.表名 |
| `srcResult` | 源端数据量 | 源端数据条数 |
| `dstResult` | 目标端数据量 | 目标端数据条数 |
| `checkResult` | 结果 | `true`（大小写不敏感）→ `通过`；其余（如 `false`）→ `不通过` |

- 忽略文件中其它列；数字列非数字、关键列为空 → 该行报错跳过；
- 与脚本的差异：脚本输出 4 列（表名/源端/目标端/校验结果）需先转换；平台导入直接读 TDM 原始导出字段，免去线下转换步骤。

### 7.4 支持格式与解析
- 复用 `app/utils/excel.py` 的 `read_tabular`：`.xlsx` 经 openpyxl、`.xls` 经 xlrd、`.csv` 经标准库 csv（已具备三格式读取能力）；
- 单文件行数上限 **50000 行**（b05 专用上限 `MAX_CHECK_IMPORT_ROWS`，不影响 b03/b04 的 5000 行上限；导入按分块预取 + 批量写入，5 万行量级可完成）；空行跳过；首行为表头。

### 7.5 校验结果所属日期与覆盖策略（已确认 D5）
- 导入时前端选择 `data_date`，**批量写入本次导入全部记录**（文件内无日期列）；
- 同一「数据日期 + 库名 + 表名」重复导入：按唯一键 `uk_check_table_date (space_id, data_date, db_name, table_name)` **覆盖更新（upsert）**，以最后一次为准；
- 文件内同一（库名,表名）重复行：以最后一行为准（文件内去重），随后按库中是否已有同日记录分别计入 `inserted` / `updated`；
- 导入结果返回 `inserted / updated / skipped / errors` 计数。

### 7.6 边界与容错
| 场景 | 行为 |
| --- | --- |
| 文件为空 / 仅表头 | 报错返回（「导入文件无数据行」），不入库、不刷新 |
| 行级错误（码值非法/数字非法/库表名为空） | 该行记入 `errors`（行号+原因）并跳过，不阻塞其它行；不产生任何置空/清空行为 |
| 全部行校验失败 | 返回成功（`inserted=0`），`errors` 含全部行明细，不入库、不刷新 |
| 导入库表**不在当前 b03 场景清单**（已确认 D6） | 正常入库、照常参与任务级刷新；导入结果返回 `not_in_list` 条数并提示「其中 N 条不在当前迁移场景的库表清单中（校验列表页不展示）」；列表页以清单为行，不展示清单外记录 |
| `data_date` 晚于今天 | 参数校验拦截 |
| 目标库表字段为空的清单行 | 无法构成关联键，两列校验列展示「—」/灰色空序列 |

### 7.7 后端接口
- `POST /b05/checks/import`（multipart：`file` + `data_date` + `template` + 可选 `scenario_id`）→ `CheckResultImportResult { inserted, updated, skipped, errors, refreshed_tasks, not_in_list }`；
- `GET /b05/checks/import-template?template=default｜tencent` → 下载导入模版/示例文件；
- 鉴权沿用 `get_actor`（登录态 / ak-sk 双鉴权）+ `require_space_member`，空间隔离。

## 8. B05-03 — 导入后自动刷新「任务迁移-基础表数据模型」

### 8.1 触发时机与刷新范围
- **时机**：导入接口内、校验结果入库提交后**同步执行**（同一请求完成，保证「导入即刷新」）；刷新异常不影响已入库结果（记录日志并在导入结果中提示）；
- **范围（增量）**：仅刷新「本次导入涉及的目标端库表」经血缘关联命中的任务，避免全量重算。

### 8.2 关联链路（已确认 D3，目标端口径）
```
b05_check_result.db_name + '.' + table_name   （目标端库表全名）
   └─ 关联 b07_lineage：output_table = 目标端库表全名
                       AND output_table_type = '正式表' AND deleted_at IS NULL（同空间）
        └─ 取血缘边上的 project_name（项目/空间名称）+ task_name（任务名称）
             └─ 关联 b04_task：project_name = b04_task.project_name
                            AND task_name = b04_task.task_name AND deleted_at IS NULL（同空间）
                  └─ 命中的 b04_task 纳入本次刷新范围
```
- `b04_task.project_name` 与 `b07_lineage.project_name` 同口径（统一自旧 `dw_project_space`）；
- `b07_lineage.output_table` 即输出表，存储形态为「库名.表名」，与校验结果库表全名一致。

### 8.3 刷新规则（每个纳入范围的任务）
1. 求该任务的**正式输出表集合 O**：血缘关联命中的 `output_table` 去重集合（`output_table_type='正式表'`；注意 O 是该任务的**全部**正式输出表，不止本次导入涉及的表）；
2. 对 O 中每张表，取 `b05_check_result` 中该表 `data_date` **最新**一条记录的 `result`（每张表独立取全历史最新，不限于本次导入日期）；
3. 判定（已确认 D7）：
   - O 中有记录的表结果**全部为「通过」** → `check_result = '通过'`；
   - 存在任一「不通过」 → `check_result = '不通过'`；
   - O 中**没有任何表**有校验记录 → `check_result = '无校验结果'`；
4. 写回 `b04_task.check_result` 与 `updated_by / updated_at`。

### 8.4 边界
| 场景 | 行为 |
| --- | --- |
| 任务有多个正式输出表 | 全部通过才判「通过」，否则「不通过」（需求原文规则；D7 细化部分输出表无记录时的判定） |
| 输出表为临时表（`output_table_type='临时表'`） | 不纳入 O |
| 校验结果库表在血缘中无记录 | 无对应任务，忽略 |
| 血缘有记录但 `b04_task` 无对应任务 | 忽略（只刷新台账已有任务） |
| 血缘缺 `project_name` / `task_name` | 无法可靠归属，跳过（不刷新） |
| 清单行目标库表为空 | 该库表按源库表名回退关联（同 §6.3 容错口径） |
| 导入历史日期数据 | 不影响更新的记录：任务级判定按每张输出表的最新日期记录计算，历史导入不会覆盖较新结论 |
| 刷新任务数 | 导入结果返回 `refreshed_tasks`（**实际发生变更**的任务数），前端提示「已刷新 N 个任务的数据校验结果」 |

### 8.5 后端实现要点
- 服务归属 `services/b05_data_check.py`；查询 `b04_task`/`b07_lineage` 可复用既有 session 与模型，**避免与 b04 service 循环依赖**；
- 聚合实现：先由本次导入的（库名,表名）集合查血缘命中任务 ID 集合（增量）；再对每个任务查 O 集合与每表最新记录（`max(data_date)` 子查询/窗口函数）；
- 事务：入库与刷新在同一事务，失败整体回滚（刷新异常按 §8.1 降级为日志+提示时，入库已提交）。

> 派生规则（未单独交互确认，按上述决策与既有约定推导，实现时默认遵循）：
> R-a `check_result` 导入允许留空并落「无校验结果」，「必选」仅约束模板必须包含该列；
> R-b 任务详情页 `check_result` 只读（系统维护），批量流转不含该字段；
> R-c 「数据校验」作为独立侧边分组（迁移执行之后、数据资产之间为「数据资产」分组，即迁移执行 → 数据校验 → 数据资产）；
> R-d `recent_days` 数组按日期降序（索引 0=昨天），与左→右展示一致；
> R-e 任务级刷新为增量范围（本次导入涉及库表→血缘→任务），但每张输出表取全历史最新记录参与判定；
> R-f 清单行目标库表为空时按源库表名回退关联（§6.3 / §8.4）；
> R-g 文件为空/仅表头才报错；全部行校验失败返回成功并带 `errors` 明细，不入库、不刷新（§7.6）；
> R-h `refreshed_tasks` 统计实际发生变更的任务数（§8.4）；
> R-i 文件内同一（库名,表名）重复行以最后一行为准（文件内去重），再按库中是否已有同日记录计入 inserted / updated（§7.5）。
