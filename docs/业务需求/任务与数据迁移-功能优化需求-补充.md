## 1. 概述

### 1.1 修订背景
原 V1.0 的 **B04-03** 规定：任务详情页的输入/输出表清单按 `b04_task.task_uri` 解析出的「任务名称 + 工作流名称」二元组精确匹配 `b07_lineage`，以规避跨工作流重名。

实际业务中存在两点偏差：
1. **数仓归属维度更贴近 `dw_project_space`**：任务所属**源端数仓项目空间**记录在 `b04_task.dw_project_space`，而非工作流；同一数仓项目空间下的同名任务（跨多个工作流）本就是同一批血缘资产。
2. **同名任务跨工作流普遍存在**：按「任务名 + 工作流名」精确匹配会把同一数仓项目空间内、同名但不同工作流的任务血缘**割裂**；按「数仓项目空间 + 任务名」聚合更能反映其全量输入输出。

故将 B04-03 的血缘关联键由 `task_uri`（任务名+工作流名）调整为 **`dw_project_space`（数仓项目名称）+ `task_name`（任务名称）**，并在同一数仓项目空间内**跨工作流合并**。

### 1.2 修订范围
| 能力 | 归属 | 本次范围 |
| --- | --- | --- |
| 任务详情输入输出表关联血缘（关联键） | `b04` + `b07` | 关联键由 `task_uri` 改为 `dw_project_space` + `task_name`；跨工作流合并；仍过滤临时表 |
| 空值兜底 | `b04` | `dw_project_space` 为空时视为无血缘，显示「暂无血缘关系」 |

**不在本次范围**：B04-01（数仓项目空间字段本身）、B04-02（导入改名）、B04-04 / B03-01（血缘弹层形态）均不变；原 V1.0 的 D3 关联键决策被本补充 **D5 取代**。

## 2. B04-03 关联键调整（修订）

### 2.1 关联逻辑（已确认 D5）
- 取当前任务的 **`dw_project_space`（数仓项目名称）** 与 **`task_name`（任务名称）** 作为关联键；
- 在 `b07_lineage` 中匹配 `project_name = dw_project_space AND task_name = task_name` 的全部边（**不限 `workflow_name`，跨工作流合并**）；
- 汇总这些边的 `input_table`（去重，作为输入表清单）与 `output_table`（去重，作为输出表清单）；
- **过滤临时表**：依据 `input_table_type` / `output_table_type`，丢弃类型为「临时表」的条目，**仅保留正式表**展示（沿用 b07 D6 仅约束血缘图渲染、不影响本清单过滤）。

### 2.2 空值兜底（已确认 D6）
- 若任务的 `dw_project_space` 为空（未填写数仓项目空间），则无法构成有效关联键 → 视为无血缘；
- 清单为空并提示「暂无血缘关系」，与「该任务在 b07 无记录」的兜底表现一致。

### 2.3 展示与交互（沿用 V1.0，不重述）
- 任务详情页输入表区、输出表区分别渲染上述正式表清单；
- 每个表名**可点击**，点击触发 B04-04 血缘对话框（以该表为根表）；
- `b04_task` 原有 `input_tables` / `output_tables` 字段**保留**（仍用于导入落库与列表概览），仅「详情页输入输出表清单」以血缘关联结果为准。

### 2.4 后端接口调整
原 `GET /b07/lineages/by-task?task_uri=...` 的入参语义需同步调整（详见总文档 §7.5）：
- **主参数**：`space_id` + `dw_project_space`（数仓项目名称）+ `task_name`（任务名称）；
- 返回结构不变：去重后的 `input_tables` / `output_tables`（含 `type`），前端按类型过滤临时表；
- 兼容建议：保留 `task_uri` 入参作为过渡（内部仍解析为 任务名+工作流名），但**本期关联以 `dw_project_space` + `task_name` 为准**；过渡期后可废弃 `task_uri` 入参。
