## 1. 背景与总体目标

本期属于「界面与可视化优化」，不改变底层数据模型与既有能力，目标有三：

1. **术语统一**：「任务台账」作为子模块名偏重「台账」语义，产品定位是「任务视图/看板」，故整体更名为「任务视图」；与之配套的「自定义台账/固化台账」同步对齐为「自定义视图」，避免「台账」一词多义。
2. **校验结果可溯源**：数据校验列表与血缘图是两张看数据质量的入口，需要互相打通——列表里点库表直接看血缘，血缘节点上直接看该表最近几天的校验结果，形成「库表 → 血缘 → 校验」的闭环。
3. **任务详情可直达**：血缘「查看详情」里已经能看到任务，但只能看不能进；本期让任务名可直达任务详情面板，与「任务迁移」里的任务详情完全一致（仅去掉在该上下文无意义的「任务输出表」入口）。

## 4. 数据校验 — 库表列调整与血缘入口（b05）

### 4.1 列表列调整（D2）

数据校验列表（`views/data-check/DataCheckList.vue`）当前列：源库表 / 目标库表 / 表类型 / 最新校验结果 / 近7天校验结果。

调整后为：**库表 / 表类型 / 最新校验结果 / 近7天校验结果**。

- 「源库表」表头改为 **「库表」**，单元格内容仍为 `db_name.table_name`（即 b03 库表清单的源端库表）；
- **移除「目标库表」列**；
- **保留「表类型」列**；
- 「库表」单元格由纯文本改为**可点击链接**（视觉沿用任务详情里「任务输出表」的链接样式：蓝色、hover 高亮）。

### 4.2 库表链接打开血缘（D3）

点击「库表」链接 → 以弹框方式打开**数据血缘对话框**（`LineageDialog`），并聚焦该表（`focus-table = db_name.table_name`），交互与任务详情里的「任务输出表」链接完全一致。

- 聚焦对象为列表显示的**库表**（`db_name.table_name`，源端口径），严格按需求原文；
- 复用现有 `LineageDialog` 组件（`v-model` + `:space-id` + `:focus-table`），与 `TaskDetailDrawer` 中打开血缘的方式统一；
- 列表页新增一个 `LineageDialog` 实例即可，无需新增组件。

> 备注：数据校验结果落库以目标端库表为口径（见《数据校验-数据校验结果导入与刷新需求》D3）。本期按需求明确「点击源端库表打开血缘」，故聚焦源端 `db.table`；若后续希望与刷新/校验口径严格对齐，可再议改为目标端，本期不调整。

## 5. 血缘管理 — 节点校验结果可视化 + 任务详情入口（b07）

### 5.1 节点左下方校验结果□（D4）

无论血缘从何处打开（数据校验列表、任务详情输出表、血缘独立页），在**每个血缘节点主体左下方**渲染数据校验结果标记：

- 取**最近 3 个自然日（T-1、T-2、T-3，不含当天）**窗口；**仅当某日确有校验结果时才渲染一个 □**——有几个有结果的日期就显示几个 □，**无结果的日期不显示灰色占位**（V1.1 调整：由「固定 3 个□（灰占位）」改为「有几个显示几个」）；
- 每个 □：
  - **绿色** = 当天校验结果为「通过」；
  - **红色** = 当天校验结果为「不通过」；
  - （无记录当日不渲染 □，不再灰显）；
- **悬浮（hover）提示**：显示该□对应日期的「源端数据量 / 目标端数据量」（取自 `b05_check_result.src_volume / dst_volume`）以及结果；
- 节点上的 □ 按时间从左到右排列（T-1 在最左，T-3 在最右）。

### 5.2 数据来源（新增后端接口）

新增 **`GET /b05/checks/by-tables`**（空间级，沿用 `get_actor` + `require_space_member` 鉴权）：

- 入参：`tables`（必填，逗号分隔的 `db.table` 列表，如 `ods_a.t1,ods_b.t2`）、可选 `days`（默认 7，取最近 N 天窗口）；
- 出参：`{ "<db.table>": [ { data_date, result, src_volume, dst_volume }, ... ] }`，每个表返回窗口内**有记录**的校验结果，按日期降序；
- 实现：对入参表名批量取 `b05_check_result`（按 `space_id + (db_name,table_name) + data_date ∈ [today-days, today-1]` 且未删除），按表聚合返回；复用 `_latest_map` 同类的批量取数逻辑，避免逐表查询；
- 前端 `LineageDialog` 在构图后，对该图所有节点表名去重，调用一次 `by-tables`，将结果以 `Record<table, DayResult[]>` 形式透传给 `LineageGraph`；`LineageGraph` 在渲染节点时计算 T-1~T-3 三个□。
- **（V1.1 缺陷修复）`by-tables` 为非关键调用**：血缘弹框的主请求 `listLineages` 不受影响；`by-tables` 在 HTTP 封装层以 `silent` 方式调用（失败不弹错误 toast），即便该接口鉴权拦截或异常，血缘图仍**正常打开并渲染**，`checkResults` 缺省为空、节点不显示 □ 即可。避免「次要校验数据取数失败」阻塞主血缘查看（解决数据校验列表打开血缘偶发 403 时弹框报错）。

### 5.3 右键「查看详情」任务名 → 任务详情面板（D5）

血缘节点右键「查看详情」打开的表详情面板（写入/读取任务列表）中，每条任务的 **「任务」名称** 改为**可点击**：

- 点击任务名 → 弹出**任务详情面板**（复用现有 `TaskDetailDrawer` 组件）；
- 查找逻辑：以该血缘记录携带的 **`project_name` + `task_name`** 去 `b04_task` 基础表定位任务（新增接口见 5.4）；
- **该面板不展示「任务输出表」区块**（其余字段——基础信息、5 维状态流转、标签、排查备注时间线——与「任务迁移」里的任务详情完全一致）；
- 通过 `TaskDetailDrawer` 新增可选属性 `hideOutputTables`（默认 `false`）实现：为 `true` 时跳过输出表查询与渲染区块；
- 面板挂载在 `LineageDialog` 内（`TaskDetailDrawer` 自带 `append-to-body`/抽屉层，嵌套在血缘弹框中显示正常）；
- 状态/标签/备注编辑在该面板内仍生效，并 `emit('changed')`（如需同步血缘面板任务列表，由 `LineageDialog` 监听后刷新，本期保持与源面板一致即可）。

### 5.4 数据来源（新增后端接口）

新增 **`GET /b04/tasks/by-key`**（空间级，沿用既有鉴权）：

- 入参：`project_name`（必填）、`task_name`（必填）；
- 出参：`TaskOut`（与列表同一序列化）；未找到返回 404 / 业务提示「未找到对应任务」；
- 实现：`b04_task` 按 `(space_id, project_name, task_name, deleted_at is null)` 取一条（任务名在同一项目空间内唯一），复用 `TaskOut` schema；
- 前端 `LineageDialog` 点击任务名时调用，拿到 `TaskOut` 后传给 `TaskDetailDrawer` 的 `:task`，并置 `:hide-output-tables="true"`。

## 10. V1.1 缺陷修复与性能优化补充

本期在 V1.0 上线验证后，针对发现的缺陷与性能瓶颈做如下补充（已在 `lineage_demo` 空间完成验证）：

### 10.1 数据校验打开血缘偶发 403（缺陷修复）

- **现象**：数据校验列表点击「库表」打开血缘弹框时，弹框报错 403。
- **根因**：血缘弹框构图后并发调用 `by-tables` 取节点校验结果；该接口为**非关键**取数（仅用于节点□），一旦被鉴权拦截或异常，旧实现会让弹框整体报错。
- **修复**：`by-tables` 在 HTTP 封装层以 `silent` 方式调用（失败不弹 `ElMessage.error`）。主血缘请求 `listLineages` 鉴权逻辑不变、不受影响；即便 `by-tables` 失败，血缘图仍正常打开渲染，`checkResults` 缺省为空、节点不显示 □。
- **影响范围**：仅前端交互降级策略；后端接口与鉴权规则无变化。

### 10.2 血缘管理检索首屏慢（性能优化）

- **现象**：血缘管理按「表名称 / 工作流名称 / 任务名称」检索首次加载慢。
- **根因**：`b07_lineage` 空间级查询未携带 `space_id` 前缀索引，触发全表扫描。
- **修复**：在 `b07_lineage` 上新增 5 个**空间作用域复合索引**（均以 `space_id` 为前缀）：
  - `idx_b07_space_workflow(space_id, workflow_name)` —— 工作流名称检索；
  - `idx_b07_space_task(space_id, task_name)` —— 任务名称检索；
  - `idx_b07_space_proj_task(space_id, project_name, task_name)` —— 项目名称+任务名称检索；
  - `idx_b07_space_input(space_id, input_table)` —— 输入表名称检索；
  - `idx_b07_space_output(space_id, output_table)` —— 输出表名称检索。
- **存量补齐**：通过 `_apply_space_additive_migrations` 在每次访问空间库时**幂等**执行 `CREATE INDEX IF NOT EXISTS`（并清理旧单列索引 `idx_b07_workflow / idx_b07_input / idx_b07_output`），`lineage_demo` 等已有空间自动补齐，无需手动迁移。

### 10.3 血缘节点□呈现调整（D4 修订）

- **变更**：由「固定 3 个□（无记录灰占位）」调整为「仅对最近 3 日内**确有校验结果的当日**渲染 □，有几个显示几个，无结果当日不显示」。
- **理由**：节点无校验数据时用灰色占位反而误导；改为「有则显、无则不显」更直观反映数据质量覆盖情况。
- **验证**：在 `lineage_demo` 空间确认有结果的节点按当日显示对应数量绿/红□，无结果节点左下角不渲染□。

### 10.4 任务迁移按钮改名（台账 → 视图）

- **范围**：除 V1.0 已覆盖的「保存为视图」按钮外，补充「**创建台账 → 创建视图**」「**添加到台账 → 添加到视图**」两类按钮，连同 `SaveViewDialog` / `AddToLedgerDialog` / `AddTasksDrawer` 的标题、提示与按钮文案一并改为「视图」（详见 §3.4）。
