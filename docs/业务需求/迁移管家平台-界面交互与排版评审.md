# 迁移管家（MigOps）平台界面交互与排版评审

## 1. 评审范围与方法

- **范围**：全局信息架构、空间内导航框架、各业务模块（b02/b03/b04/b07）页面交互与排版；
- **方法**：以产品经理视角对照《完整需求文档》逐条走查主用户旅程（登录 → 选空间 → 开展业务），结合前端实际实现（路由表、`SpaceLayout.vue` 导航、各列表页交互）定位设计不合理处；
- **输出**：问题清单（§3，按严重度分级）+ 新的功能排版方案（§4）+ 原型索引（§5）。

**一句话结论**：当前实现是「按模块纵向生长」的自然结果——功能齐备但**信息架构停留在模块平铺阶段**；建议以「侧边分组导航 + 场景上下文常驻 + 台账/标签收纳进任务迁移」为主线重构空间视图框架，并对补充任务等跨页流程做内嵌化改造。

## 3. 问题清单

### I1【P0】空间内导航 7 个入口平铺，无分组、无层级、无图标

- **现状**：`SpaceLayout.vue` 顶部一排 tab：空间概览 / 项目资料索引 / 数据迁移 / 任务迁移 / 任务台账 / 血缘管理 / 标签管理。
- **问题**：
  1. **父子关系被拉平**：「任务台账」是任务迁移的子能力（数据源、操作都依附 `b04`），「标签管理」仅服务 `b04` 任务（需求 D9 仅因 UI 独立才设为一级菜单），三者平级展示使用户难以建立心智模型；
  2. **「空间概览」语义错位**：概览是落地页而非业务模块，与 6 个业务模块并列排在导航首位，弱化了业务入口；
  3. **7 个纯文字 tab 无图标无分组**，认知负荷高，且无数量提示（如台账数、标签数）；
  4. 后续若 b05 校验、b99 看板上线，导航将膨胀到 9+ 项，平铺结构不可持续。
- **影响**：用户找不到功能、不理解模块关系；导航成为平台扩张瓶颈。
- **建议**：改为**侧边分组导航**（图标 + 文字 + 徽标）：业务按阶段分组（资料准备 → 迁移执行 → 数据资产）；「任务列表 / 任务台账 / 标签管理」收纳为「任务迁移」分组下的子项；「空间概览」回归为落地页（侧边首项，不占业务分组）。详见原型 P2/P4。
- **对应需求**：《完整需求文档》§3.1、§5.3.4、§5.3.5。

### I2【P0】迁移场景（Scenario）上下文不共享，切模块即丢失

- **现状**：b03 数据迁移与 b04 任务迁移各自在页面内维护场景选择（`ScenarioBar`），场景状态不跨页面保持。
- **问题**：
  1. 用户从「数据迁移」切到「任务迁移」后场景重置，需重新选择，操作断裂；
  2. 同一空间多场景时（如同时跑 `hive→hive` 与 `holo→starrocks`），反复选择场景成本高；
  3. 场景是空间下的核心工作上下文（两个模块共用同一概念），却散落在各页面内部，状态无法沉淀。
- **影响**：多场景空间下误操作风险高（在错误场景下导数据/改状态）。
- **建议**：场景选择状态**提升为空间级 store**，在 b03/b04 页面工具栏常驻显示且跨导航保持；场景名在页面标题区强提示（如「任务迁移 · holo→starrocks」）。详见原型 P4。
- **对应需求**：《完整需求文档》§5.2.1、§5.3.1。

### I3【P1】概览页 Panel 区与「项目空间管理」页双入口职责重叠

- **现状**：概览页 `/` 有「我的项目空间」Panel 区（展示 + 进入空间）；另有 `/b01/spaces` 项目空间管理页（`SpaceList`）展示空间列表。
- **问题**：
  1. 两处展示内容高度重合（名称/状态/进展），用户困惑「看空间去哪里」；
  2. 权限差异（创建按钮仅 L0/L1、管理操作）在两处各自实现，易出现行为不一致；
  3. 概览页同时承担「工作台（快速进入）」与「空间管理」两种心智，定位不清。
- **影响**：入口冗余、维护双份逻辑。
- **建议**：**合并为统一入口**——概览页 Panel 区即空间总览（工作台视角：搜索/筛选/进入 + L0/L1 行内管理操作：编辑/成员/状态）；`/b01/spaces` 管理页保留给纯管理场景但明确区分（或直接收敛掉，由 Panel 区承担）。本期建议：Panel 区增加行内快捷操作（编辑/成员），与 SpaceList 打通复用组件。
- **对应需求**：《完整需求文档》§5.0.1、§4.4。

### I4【P0】「补充任务」流程整页跳转，链路长、易迷失

- **现状**（需求 §5.3.3-4 已确认的实现）：台账详情页 →「补充任务」→ 跳转任务列表页（`?addToView=<viewId>&scenarioId=`）→ 顶部上下文横幅 → 搜索勾选 →「添加到台账（N）」→ 对话框 → 成功返回。
- **问题**：
  1. 整页跳转 + query 参数传递上下文，用户离开当前台账后容易迷失（尤其多标签页/多台账并行时）；
  2. 「返回原台账」依赖前端路由判断，刷新/后退行为不可控；
  3. 为了一次性加几条任务，被迫走完「离开 → 搜索 → 勾选 → 加 → 返回」五步。
- **影响**：固化台账补充成员是高频补救操作，流程损耗直接劝退。
- **建议**：**内嵌化**——台账详情页内直接打开「补充任务」抽屉/对话框（内嵌筛选栏 + 任务多选表格，默认展示当前场景未在台账内的任务），确认即加入并原地刷新，无需离开页面。Before/After 对比见原型 P5。
- **对应需求**：《完整需求文档》§5.3.3-4。

### I5【P1】台账概念过多，内部机制术语直接暴露给用户

- **现状**：dynamic/fixed 两种模式 + 「保存为台账」/「勾选创建」两种创建 + 「移除转固化」+「补充任务」+「动态自动固化」。
- **问题**：
  1. `view_mode`/`filter_config`/成员表等实现概念渗透到 UI（模式标签「动态引用/固化台账」对业务用户偏技术）；
  2. 「移除即转固化」「补充即固化」的隐式转换规则，用户无感知时会出现「台账怎么变了」的困惑；
  3. 创建时直接让用户选模式，缺乏场景化引导。
- **影响**：学习成本高；固化/动态误用导致台账结果不符合预期。
- **建议**：
  - 术语通俗化：「动态引用 → 自动更新」；「固化台账 → 固定名单」；
  - 创建引导化：以任务目标提问（「想让名单随筛选条件自动更新吗？」）而非直接展示模式单选；
  - 转换显式化：移除/补充触发模式变化时，弹窗明确告知「此操作将把台账转为固定名单，之后不再自动更新」。
- **对应需求**：《完整需求文档》§5.3.3。

### I6【P0】台账相关路由层级不一致

- **现状**：台账列表 `/space/:spaceId/ledgers`，台账详情 `/space/:spaceId/tasks/views/:viewId`。
- **问题**：同一子模块使用两套路由前缀（`ledgers` vs `tasks/views`），面包屑、返回逻辑、导航高亮判断混乱；「自定义台账」标题与「任务台账」入口名称也不一致（前者是详情页 meta title）。
- **建议**：统一为 `/space/:spaceId/tasks/ledgers`（列表）与 `/space/:spaceId/tasks/ledgers/:viewId`（详情），导航名称统一为「任务台账」。
- **对应需求**：《完整需求文档》§3.1、§5.3.4。

### I7【P1】血缘管理与任务迁移概念重叠但零联动

- **现状**：b07 血缘的 `workflow_name / task_name / script_name` 与 b04 任务台账同源语义（需求 §8 明确本期不强制联动），但两边各自录入，无跳转路径。
- **问题**：
  1. 同一工作流的脚本信息在 b04（任务导入）与 b07（工作流管理录脚本）重复录入；
  2. 用户在 b04 看到任务的输入/输出表，想看看血缘必须去血缘页重新搜索，上下文断裂；
  3. 长期看，「工作流」在平台内有两个维护源，有数据分裂风险。
- **建议**（最小联动，不打破本期范围）：b04 任务详情抽屉增加「查看血缘」入口（携带任务的工作流/输入输出表跳转 b07 并预置检索）；b07 工作流选项可提示「该工作流已存在于任务台账」。
- **对应需求**：《完整需求文档》§5.4.1、§5.3.1。

### I8【P1】「整体进展」手工维护与真实业务数据割裂

- **现状**：空间头部与概览 Panel 显示手工维护的 `overall_progress`（0~100）；空间内 b03/b04 存在大量真实进度数据（迁移状态分布、任务状态分布），但空间概览页「不含量化统计」（D15）。
- **问题**：
  1. 手工进展易失真（维护不及时则与真实进度脱节，如手工 80% 而任务大量未开始）；
  2. 空间概览页作为落地页只有信息没有「进展洞察」，价值浪费；
  3. 手工与自动两套口径并存但无关联展示，用户不知道该信哪个。
- **建议**：空间概览页增加**真实统计区**（任务状态分布、迁移完成率、资料/台账数量等，由现有数据聚合，不新建表）；手工「整体进展」降级为「项目自评」与真实统计并列展示；二期再切换为自动计算（D13 已预留）。
- **对应需求**：《完整需求文档》§5.0.2、§4.4、§10.2。

### I9【P2】状态术语与色彩跨模块不统一

- **现状**：b03 状态（未迁移/迁移中/已完成/异常）、b04 状态（未开始/改造完成/…/挂起/废弃）各自定义；设计令牌已规定语义色，但跨模块同义状态（如「进行中」）的色值与标签风格需核对一致性。
- **建议**：沉淀**全局状态色板**并组件化（`StatusTag`）：未开始=灰 `#bdc3c7`、进行中=蓝 `#1a73e8`、完成=绿 `#188038`、异常=红 `#e53935`、旁路/挂起=琥珀 `#f2a100`；b03/b04 状态值映射到同一色板，术语保留业务差异但颜色语义一致。
- **对应需求**：《完整需求文档》§8-10、`CODEBUDDY.md` §6.4.2。

### I10【P2】空态引导不完整、不一致

- **现状**：血缘页有空态（「请输入表名进行血缘检索」），其他模块空态（无场景、无数据、无台账）风格与引导动作不统一。
- **建议**：统一空态组件（图标 + 一句说明 + 主行动按钮，如「创建第一个迁移场景」），按模块预置文案与动作。
- **对应需求**：全局体验一致性。

### I11【P2】缺少全局表名检索

- **现状**：表名散落在 b03 库表清单、b04 输入/输出表、b07 血缘三处，无统一检索入口。
- **建议**（二期）：顶栏全局搜索支持表名 → 聚合展示「该表在数据迁移中的状态 / 相关任务 / 血缘图入口」。
- **对应需求**：《完整需求文档》§10.2。

### I12【P1】空间头部信息密度高、层级弱

- **现状**：`SpaceLayout` 头部卡片内，标题/状态/code/路线/角色/成员/进展/备注全部纵向平铺在一张卡内。
- **问题**：主次不分，视觉噪音大；「我的角色/成员数」等次要信息与空间名称争夺注意力。
- **建议**：头部重排为**左右两区**——左区：空间名称（主标题）+ 状态标签 + 源→目标路线 + space_code；右区：我的角色、成员数、整体进展（紧凑小组件），备注收起为 tooltip 或次要行。详见原型 P2。
- **对应需求**：《完整需求文档》§5.0.2。

### I13【P2】导航无图标、无数量徽标

- **现状**：空间导航纯文字链接；标签管理因 V1.1 才独立，视觉权重与其他成熟模块相同。
- **建议**：侧边导航加图标；任务台账/标签管理显示数量徽标（如「任务台账 · 12」），降低进入成本。详见原型 P2/P4。
- **对应需求**：《完整需求文档》§3.1。

## 4. 新的功能排版方案

### 4.1 新信息架构（导航重构）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：Logo ｜ 概览 ｜ 项目空间 ｜           用户信息/退出      │
├──────────┬───────────────────────────────────────────────────┤
│ 侧边导航  │ 空间头（常驻）                                     │
│ （分组）  │  空间名称 + 状态  ｜ 场景切换器* ｜ 我的角色·成员·进展 │
│          ├───────────────────────────────────────────────────┤
│ ▸ 空间概览│                                                   │
│          │                  内容区（模块页面）                  │
│ 资料准备  │                                                   │
│  项目资料  │                                                   │
│          │                                                   │
│ 迁移执行  │                                                   │
│  数据迁移  │                                                   │
│  任务迁移▶ │  （子导航 tab：任务列表 ｜ 任务台账 ｜ 标签管理）    │
│          │                                                   │
│ 数据资产  │                                                   │
│  血缘管理  │                                                   │
└──────────┴───────────────────────────────────────────────────┘
  * 场景切换器仅在 b03/b04 相关页面激活，状态空间级保持（I2）
```

**变更点对照**：

| # | 现状 | 新方案 | 解决问题 |
| --- | --- | --- | --- |
| 1 | 顶部 7 tab 平铺 | 侧边分组导航（图标+徽标） | I1、I13 |
| 2 | 任务台账/标签管理一级平铺 | 收纳为「任务迁移」子导航 | I1、I5 |
| 3 | 场景各页面自持 | 场景切换器空间级常驻（b03/b04 激活） | I2 |
| 4 | 补充任务整页跳转 | 台账详情内嵌「补充任务」抽屉 | I4 |
| 5 | ledgers / tasks/views 双前缀 | 统一 tasks/ledgers 路由 | I6 |
| 6 | 空间头平铺 | 头部左右分区、主次分层 | I12 |
| 7 | 空间概览无统计 | 增加真实统计区 + 项目自评 | I8 |

### 4.2 任务迁移模块内部排版（子导航）

```
任务迁移（分组）
├─ 任务列表     任务台账表格 + 筛选栏 + 内联打标 + 勾选创建台账/添加到台账
├─ 任务台账     台账清单表格（模式标签 + 任务数）→ 详情（筛选叠加 + 操作 + 内嵌补充任务）
└─ 标签管理     标签 CRUD（分类分组展示）+ 已关联任务数
```

### 4.3 关键流程改造（Before / After）

| 流程 | Before（现状） | After（新方案） |
| --- | --- | --- |
| 补充任务 | 台账详情 → 跳转任务页 → 勾选 → 添加 → 返回（5 步，离开页面） | 台账详情 → 内嵌抽屉搜索勾选 → 确认（3 步，不离开） |
| 创建固化台账 | 任务列表「保存为台账」→ 弹窗选模式 | 勾选任务 →「创建台账」→ 引导式二选一 → 自动固定名单 |
| 查看任务血缘 | 去血缘页重新搜索表名 | 任务详情「查看血缘」→ 带上下文跳转 b07 预置检索 |
