# 迁移管家（MigOps）血缘管理 — 临时表钻取优化需求

> 文档版本：V1.0 ｜ 编写日期：2026-10-24 ｜ 状态：需求确认版（关键决策见 §7，已交互确认）
> 适用范围：血缘管理（`b07`）——临时表节点的上下游钻取与右键详情面板，需以「项目空间 + 工作流名称 + 任务名称」三元组定位钻取；正式表保持 V2.0 既有逻辑不变。并支持从详情面板跳转 `b04` 任务迁移对应任务。
> 配套文档：[`血缘管理-数据血缘需求.md`](./血缘管理-数据血缘需求.md)（上位需求，V2.0，临时表行为见 D5 / R2）、根目录 [`CODEBUDDY.md`](../../CODEBUDDY.md)（开发规范）、[`迁移管家平台-完整需求文档.md`](./迁移管家平台-完整需求文档.md)（平台总 BRD）

## 1. 概述

### 1.1 背景与目标
在 V2.0 血缘需求中，临时表仅在同「工作流 + 脚本」上下文内与上下游关联（D5），钻取由前端 `buildGraph` 以「表名 + 工作流 + 脚本」维度构图。但在实际迁移项目中，同一临时表名（如 `tmp_stage`）往往会被**多个任务 / 工作流**产出，甚至跨**项目空间**复用。仅以「表名 + 工作流 + 脚本」定位，存在钻取到错误实例、下游/上游血缘串扰的风险。

本需求将临时表的钻取定位维度升级为 **「项目空间 + 工作流名称 + 任务名称」三元组**，确保钻取的是唯一正确的临时表实例；同时让右键详情面板暴露该三元组并支持**一键跳转 `b04` 任务迁移**，打通血缘与任务的跨模块联动。正式表保持 V2.0 全局按表名关联的逻辑不变。

### 1.2 范围
- **涉及前端**：`LineageGraph.vue`（临时表节点 `+/−` 上下游钻取构图）、`NodeDetailPanel.vue`（临时表详情面板的三元组展示与跳转）、`SearchBar.vue`（不涉及，仅说明临时表不进检索）、空间布局路由（跳转 `b04`）。
- **涉及后端**：`b07` 前端 `buildGraph` 临时表邻接构图逻辑升级（`b07_lineage` 边已含 `project_name / workflow_name / task_name`，无需新增字段）；`b04` 任务台账需提供「按 工作流 + 任务（项目空间内）定位任务」的入口/路由承接（跨模块协调，见 §3.3、§8）。
- **涉及库**：`mig_<space>_db.b07_lineage`（复用既有字段，**不新增表/字段**）。

### 1.3 术语
| 术语 | 含义 |
| --- | --- |
| 临时表 | 表类型之一；仅在「项目空间 + 工作流 + 任务」上下文内与上下游关联（本需求升级维度） |
| 钻取定位三元组 | 项目空间 + 工作流名称 + 任务名称，用于唯一锁定临时表实例 |
| 下游 / 上游 | 相对当前表，下游 = 当前表写入的目标表；上游 = 写入当前表的来源表 |
| 跨模块跳转 | 从 `b07` 血缘详情面板跳转至 `b04` 任务迁移对应任务/工作流页面 |

## 3. 功能设计

### R1 临时表上下游钻取按三元组定位

#### 3.1.1 功能描述
用户在临时表节点上点击左侧 `+/−`（上游）或右侧 `+/−`（下游）展开时，前端 `buildGraph` 在构图邻接时，以「当前临时表节点对应的 `project_name + workflow_name + task_name`」作为定位键去解析其一度邻居，**而非仅按表名全局匹配**。同一临时表名出现在不同工作流/任务时，仅展开当前上下文对应的那一分支，其余实例不串入。

#### 3.1.2 交互与界面
- 节点左（上游）/ 右（下游）`+/−` 展开收起交互与 V2.0 一致（带数量角标、缓动居中 0.4s `cubic-bezier`、拖拽关闭过渡）。
- 右键菜单「展开上游全部 / 收起上游 / 展开下游全部 / 收起下游」对临时表同样遵循三元组定位（覆盖下游 + 上游）。
- **正式表**：保持 V2.0 既有逻辑——按表名全局关联上下游，不受三元组影响（本需求**不改动**正式表行为）。

#### 3.1.3 权限与可用性
- **适用角色**：全部（L0/L1/L2），与 V2.0 血缘模块一致；无新增权限控制。
- 仅影响临时表钻取构图逻辑，与既有检索、解析入库等能力并存。

#### 3.1.4 后端接口 / 数据变更
- `b07` 侧**无新增接口**；三元组定位在前端邻接构图内完成。
- 数据层无变更（`project_name / workflow_name / task_name` 已存在于 `b07_lineage`）。

### R2 临时表右键详情面板展示三元组

#### 3.2.1 功能描述
右键临时表节点 → 「查看详情」→ 右侧浮层 `NodeDetailPanel`（样式对齐 §6.4.6 浮层：圆角 `10px`、阴影 `0 8px 24px`、白底）。在既有的「写入任务 / 读取任务」选项卡之上，新增**上下文信息区**，展示该临时表实例的归属三元组。

#### 3.2.2 交互与界面
- 上下文信息区展示：
  - 项目空间（只读文本 / 或带跳转，见 R3）
  - 工作流名称（可跳转，见 R3）
  - 任务名称（可跳转，见 R3）
- 既有任务明细（任务名、项目、任务类型、脚本、对侧表名、复制）保持不变。
- 正式表详情面板**不受此三元组影响**，维持 V2.0 既有展示。

#### 3.2.3 权限与可用性
- 适用角色：全部，与 R1 一致。
- 仅临时表节点触发三元组上下文；正式表走原详情逻辑。

#### 3.2.4 后端接口 / 数据变更
- 无新增接口/字段；展示数据来源于 `b07_lineage` 边既有 `project_name / workflow_name / task_name`。

### R3 详情面板三元组可跳转 b04 任务迁移

#### 3.3.1 功能描述
点击详情面板中的「工作流名称」「任务名称」项，跳转至 `b04` 任务迁移的**对应任务 / 工作流**页面；「项目空间」项可跳转至该空间概览。在 `b07` 与 `b04` 之间首次建立实际联动（V2.0 §8 仅字段命名一致、未联动）。

#### 3.3.2 交互与界面
- **定位契约**：跳转携带 `(space_code / space_name, workflow_name, task_name)`，由 `b04` 在所属空间内按「工作流 + 任务」定位展示对应任务台账。
- **无匹配兜底**：若 `b07` 血缘由脚本解析入库、当前空间 `b04` 中无对应任务记录（脚本自由文本未绑定任务），则对应项**置灰 / 不可跳转**，并提示「未找到对应任务（可能尚未在任务迁移中登记）」。
- 跳转项 hover 态：蓝底 `#eef4ff`、蓝字 `#1a73e8`（对齐 §6.4.6 上下文菜单/hover 态）。

#### 3.3.3 权限与可用性
- 跳转目标受 `b04` 任务迁移既有权限约束；`b07` 侧不新增权限判断。
- 与 V2.0 §8 边界一致：本需求只在 `b07` 侧定义跳转契约与兜底；`b04` 侧承接路由为跨模块协调项。

#### 3.3.4 后端接口 / 数据变更
- `b07` 侧**无新增接口**；跳转参数为 `{ space, workflow_name, task_name }`。
- `b04` 侧（协调项，非本需求实现）：需提供「按 项目空间 + 工作流 + 任务 定位任务」的路由/查询入口，承接 `b07` 跳转。

## 4. 数据模型与接口变更

### 4.1 数据模型
- **不新增表 / 字段**：钻取所需三元组 `project_name / workflow_name / task_name` 已存在于 `mig_<space>_db.b07_lineage`（见 V2.0 §4.2）。
- 仅前端 `buildGraph` 构图逻辑由「表名 + 工作流 + 脚本」升级为「项目空间 + 工作流 + 任务」定位键；数据层无变更。

### 4.2 接口
- `b07` 侧：沿用 `GET /lineages`（取全量边客户端构图），无新增接口；三元组定位在前端邻接构图内完成。
- `b04` 侧（协调项）：提供「按 项目空间 + 工作流 + 任务 定位任务」的路由/查询入口，承接 `b07` 跳转。

---

## 5. 非功能性约束

### 5.1 统一响应与分层（沿用 CODEBUDDY.md §5）
- `b07` 不新增接口，无变更；`b04` 承接路由沿用统一信封 `{code,message,data,trace_id}` 与 router→service→repository→model 分层。

### 5.2 界面视觉（沿用 CODEBUDDY.md §6.4）
- 临时表节点着色：琥珀橙填充 `#fef7e0` / 描边 `#f2a100`（与 V2.0 一致）；详情面板浮层圆角 `10px`、阴影 `0 8px 24px`、白底；跳转项 hover 蓝底 `#eef4ff` 蓝字 `#1a73e8`（对齐 §6.4.6）。
- 类型/状态采用「颜色编码 + 文字标签」双标识。

### 5.3 隔离与规范
- 血缘数据仍按空间库 `mig_<space>_db` 隔离；三元组中的「项目空间」即当前空间上下文，跨空间不聚合（遵循 V2.0 D1）。

## 7. 已确认决策汇总（2026-10-24）

| 编号 | 议题 | 决策 |
| --- | --- | --- |
| D1 | 钻取覆盖范围 | 下游钻取 + 上游钻取 + 右键详情面板**全部**使用「项目空间 + 工作流名称 + 任务名称」三元组定位（超出原文仅「下游+详情」的范围，按确认包含上游）；正式表保持 V2.0 逻辑不变 |
| D2 | 三元组是否跳转 b04 | 详情面板中「项目空间/工作流/任务」**可点击跳转**至 b04 任务迁移对应任务/工作流，强化跨模块联动 |
| D3 | 与 V2.0 文档关系 | 新建本独立文档；定位为「在 V2.0 D5 基础上细化临时表钻取定位维度」，**V2.0 原文不改动** |

> 决策均经交互式确认（AskUserQuestion）。本需求有意将临时表钻取维度由 V2.0 的「工作流+脚本」细化为「项目空间+工作流+任务」，属对 D5 的细化而非冲突。
