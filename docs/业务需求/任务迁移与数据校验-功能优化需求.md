## 1. 概述

### 1.1 背景与目标
任务迁移模块经过前几期建设（基础表重塑、数据校验结果字段、URI 隐藏等）后，现场使用中暴露出四类问题；数据校验模块则缺少一个「手动重算任务级校验结论」的入口：

1. **模板字段顺序不可调**：空间级迁移模板的字段顺序固定按预设排列，团队希望按自己的查阅习惯调整查询列表的列顺序（如把「迁移负责人」提到前面）；
2. **导入必填过严**：导入基础数据时 9 个锁定必填字段都必须有值，现场 partial 台账（先导核心列、状态后补）被迫编造填充值；
3. **详情首屏信息密度**：任务名称/工作流挤在同一行、项目名称与负责人同行，核心三要素（项目/工作流/任务）不突出；
4. **输出表不可见**：任务详情看不到该任务的血缘输出表，校验「这个任务产出哪些表」要跑去血缘页检索；
5. **校验结论重算入口缺失**：血缘修正或历史数据补导后，只能再导一次文件才能刷新任务级「数据校验结果」，缺少一键重算。

本期以「小步优化」为原则补齐上述五点，不改变既有数据模型语义（除必填放宽导致的列可空化）与既有能力。

### 1.2 范围
| 能力 | 归属 | 本期范围 |
| --- | --- | --- |
| 模板字段拖动排序 | `b04` | 配置字段模板对话框内整行拖动（基础+扩展统一列表），order 决定查询列表列顺序与导入模板列顺序（D1/D7） |
| 导入必填放宽 | `b04` | 导入行级仅强制「项目名称、任务名称」；其余字段留空落 NULL（D2/D3） |
| 详情三行布局 | `b04` | 项目名称、工作流名称、任务名称各占一行 |
| 详情任务输出表 | `b04` + `b07` | 按 项目名称+任务名称 查血缘输出正式表，可点击弹出血缘对话框（D4） |
| 刷新任务状态 | `b05` → `b04` | 数据校验列表页按钮，全量重算任务级数据校验结果（D5/D6） |

**不在本期范围**：
- 模板字段的新增/删除/改名/必勾选逻辑变化（仅新增排序能力）；
- 任务详情的「输入表」展示（本期仅输出表；输入表如需另行规划）；
- 血缘页（b07）本身的任何改动；
- 数据校验结果的编辑/删除入口（仍仅导入）。

### 1.3 术语
| 术语 | 含义 |
| --- | --- |
| 字段顺序（order） | 空间级迁移模板 `config_json.fields[].order`，升序即展示顺序 |
| 扩展字段物理列（f_n） | 扩展字段按「扩展字段间的相对顺序」映射到 `b04_task_ext.f_1…f_n`；相对顺序变化即重映射 |
| 任务输出表 | 该任务在血缘中的输出表（`b07_lineage.output_table`）中表类型为「正式表」的去重清单 |
| 刷新任务状态 | 按表级数据校验结果重算任务级「数据校验结果」字段（逻辑同《数据校验-数据校验结果导入与刷新需求》§8） |

## 3. B04-07 — 配置字段模板支持拖动排序

### 3.1 功能描述
「配置字段模板」对话框中，全部字段（基础字段 + 扩展字段）合并为一个列表，支持**整行拖动上下移动**调整顺序；保存后按新顺序重排 `order`（1..N 连续）。模版顺序决定**任务查询列表的列顺序**与**导入基础数据 Excel 模板的列顺序**（D7）。

### 3.2 交互规则（已确认 D1）
- **统一列表**：不再分「基础字段表 / 扩展字段卡」两个独立区域，合并为一张字段表：字段名 / 必填 / 列表展示 / 拖拽手柄；
- **整行拖动**：每行行首提供拖拽手柄（⠿ 图标），按住可上下拖动，拖动时有占位提示，松手落位；
- **扩展字段重映射提示**：扩展字段之间的相对顺序发生变化时（将改变 `f_n` 物理列映射，已有扩展数据按新顺序展示），保存时弹出提示告知影响，用户确认后保存；
- **必填锁定不变**：9 项锁定必填字段仍不可取消必选（含「数据校验结果」）；「列表展示」勾选行为不变；
- **任务名称列特例**：查询列表中「任务名称」为固定首列（现状），模版内调整其顺序不改变该固定列位置。

### 3.3 顺序的作用面（已确认 D7）
| 作用面 | 规则 |
| --- | --- |
| 查询列表列顺序 | `TaskMigrationList` 按 `order` 升序渲染模板列（现状机制，无需改动） |
| 导入模板列顺序 | 任务导入 Excel 模板列按 `config_json.fields` 数组顺序生成（数组顺序与 `order` 保持一致，拖动保存时同步重排） |
| 扩展字段 f_n 映射 | 扩展字段间的相对顺序 → `f_1…f_n`（现状机制，顺序变化即重映射，见 §3.2） |

### 3.4 后端变更要点
- 模板 schema 无需变更：`order` 唯一性校验已存在，保存时由前端重排为 1..N；
- `build_default_template_config` / `seed_default_template` 不变（新空间仍按默认顺序初始化）。

### 3.5 前端变更要点
- `TemplateConfigDialog.vue`：字段表合并基础+扩展；新增拖拽手柄与上下移动交互（拖动库或原生 HTML5 drag 实现，二选一，不新增重依赖为前提）；保存前校验 order 连续唯一；扩展字段相对顺序变化时给出 §3.2 提示；
- 保存 payload：`config_json.fields` 数组顺序与 `order` 值保持一致。

## 4. B04-08 — 导入基础数据仅强制「项目名称、任务名称」

### 4.1 功能描述
导入基础数据（Excel/CSV）的行级校验放宽：**仅「项目名称」「任务名称」不允许为空**，其余字段（含原 9 项锁定必填中的迁移负责人、5 维状态、数据校验结果等）均允许为空。

### 4.2 模板必选配置的保留（已确认 D2）
- 配置字段模板中的「必选」勾选与 9 项锁定必填**保持不变**（模板仍须包含并勾选这些字段，决定导入模板列与必选语义）；
- 变化的只是**导入行级校验**：不再因非两关键字段为空而报错。

### 4.3 留空落库规则（已确认 D3：一律 NULL）
| 字段组 | 留空时落库 |
| --- | --- |
| 项目名称 / 任务名称 | 不允许为空 → 该行错误「必填字段[项目名称]缺失」/「必填字段[任务名称]缺失」 |
| 归属环境、任务活跃状态、迁移状态、双跑调度状态、数据校验结果、数据校验状态、客户验收状态、迁移负责人、归属业务、任务类型、备注、工作流名称 | 一律落 `NULL` |

- 为实现 NULL 落库，`b04_task` 的 `active_status / migration_status / dualrun_status / env / check_result / migration_owner` 由 NOT NULL **改为可空，并移除列默认值**（SQLAlchemy 对显式 None 会触发 Python 侧默认值、对 server_default 会省略列让库默认值触发，二者均导致无法落 NULL；任务创建仅经导入路径显式传值，无需默认值）；存量数据不受影响；
- 空间库增量 DDL 增加「NOT NULL → 可空」的幂等 MODIFY 逻辑（与新增列补齐同机制）；
- 覆盖导入时，空值同样参与更新（即覆盖为空/NULL），与「允许为空」语义一致；
- 任务 URI 生成规则不变：`项目名称 or 'default' :// 任务名称 @ 工作流名称 or 任务名称`。

### 4.4 交互与提示
- 导入对话框的模式提示补充：「仅项目名称、任务名称为必填，其他字段可留空」；
- 行级错误仅剩：两关键字段缺失、状态/校验结果非法取值、互填规则（工作流与任务不能全空——任务名称必填后实际只影响工作流回填）。

## 5. B04-09 — 任务详情基础信息三行布局

### 5.1 功能描述
任务详情抽屉（`TaskDetailDrawer`）基础信息区中，**项目名称、工作流名称、任务名称分别占一行**（各 `span=2`），替代原两列并排布局，核心三要素一眼可读。

### 5.2 布局规则
- 顺序：项目名称 → 工作流名称 → 任务名称（各一行，等宽字体展示任务/工作流）；
- 其余字段（迁移负责人、归属环境、归属业务、任务类型、任务URI、备注、更新时间）布局与位置不变；
- 状态维度区、标签区、排查备注区位置不变。

## 6. B04-10 — 任务详情新增「任务输出表」

### 6.1 功能描述
任务详情抽屉新增「**任务输出表（血缘·正式表）**」区域：按当前任务的**项目名称 + 任务名称**查询血缘输出表，仅展示表类型为「正式表」的去重清单。该区域**不作为表模型字段**（不落 `b04_task`），实时查询血缘获得。

### 6.2 数据来源与规则
- 接口：复用既有 `GET /b07/lineages/by-task?space_id=&dw_project_space=&task_name=`（B04-03 补充需求的 D5 关联键：`project_name + task_name`，跨工作流合并、去重）；
- 过滤：仅展示 `output_table_type='正式表'` 的输出表；临时表不展示；
- 项目名称为空时按 `'default'` 参与关联（与任务 URI 生成口径一致）；
- 空态：「暂无输出表（血缘中无该任务的正式输出表记录）」。

### 6.3 位置与交互（已确认 D4/D8）
- **位置**：基础信息区之后、「状态维度」之前；
- **标题**：「任务输出表（血缘·正式表）」，可附数量徽标（如 `任务输出表 · 3`）；
- **表名可点击**：点击任一输出表名弹出既有血缘对话框 `LineageDialog`（固定该表为根表、无检索栏、可上下钻取、节点右键详情——与数据迁移页表名点击体验一致，复用 B04-04 弹层）；
- **加载**：抽屉打开时与排查备注、标签一并加载（loading 态）。

## 7. B05-04 — 数据校验列表「刷新任务状态」按钮

### 7.1 功能描述
数据校验列表页头部操作区（「导入校验结果」按钮旁）新增「**刷新任务状态**」按钮：一键按当前**表级数据校验结果**重算**任务级「数据校验结果」字段**，逻辑与《数据校验-数据校验结果导入与刷新需求》§8 完全一致（库表 → 血缘输出正式表 → 项目名称+任务名称 → `b04_task.check_result`；多输出表全部通过才为通过；只按有记录的表判定；全无记录置「无校验结果」）。

### 7.2 行为规则（已确认 D5/D6）
- **范围（D5）**：**全量刷新当前空间**——对空间内所有存在校验记录的库表执行关联与判定（不限 b03 场景、不限当前筛选）；
- **触发（D6）**：点击后按钮进入 loading，**无需二次确认**；完成后 `ElMessage` 提示「已刷新 N 个任务的数据校验结果」并刷新当前列表；
- **返回**：`{ refreshed_tasks: N }`（N = 实际发生变更的任务数）；
- **边界**：空间内无任何校验记录 → 提示「已刷新 0 个任务的数据校验结果」；刷新异常不影响列表数据（错误提示）。

### 7.3 后端接口
- 新增 `POST /b05/checks/refresh-tasks`（参数 `space_id`）→ `{ refreshed_tasks }`；
- 实现：复用 `refresh_task_check_results`，入参 `touched_keys=None` 表示全量（取空间内所有有校验记录的库表键执行关联），其余判定逻辑不变。

## 8. 数据模型变更汇总

### 8.1 `b04_task` 列可空化（配合 B04-08，D3）
| 列 | 变更 |
| --- | --- |
| `active_status` | NOT NULL → 可空，**移除默认值** |
| `migration_status` | NOT NULL → 可空，**移除默认值** |
| `dualrun_status` | NOT NULL → 可空，**移除默认值** |
| `env` | NOT NULL → 可空，**移除默认值** |
| `migration_owner` | NOT NULL → 可空（本就无默认值） |
| `check_result` | NOT NULL → 可空，**移除默认值** |

- 无新表、无新列；`b04_migration_template` 模板结构不变（仅 order 重排）；
- DDL：空间库增量 DDL 增加幂等「MODIFY 为可空」（仅当当前为 NOT NULL 时执行）；新空间建表按可空、无默认值定义；
- 默认值必须移除的原因：SQLAlchemy 对显式 None 会触发 Python 侧 `default`、对 `server_default` 会省略列让库默认值触发，二者都会导致导入空值无法落 NULL；任务创建仅经导入路径（显式传值/传空），无其他免填写插入路径。
