1文档概述

1.1 编写目的

本文件旨在为"迁移管家平台"的建设提供完整、清晰的业务需求定义，指导产品设计与研发实施。文档面向以下读者：

读者角色关注重点
产品经理功能范围、业务流程、原型设计
研发工程师功能模块拆分、字段定义、数据模型
项目管理者平台定位、价值目标、看板指标
迁移实施工程师操作流程、台账管理、校验机制

1.2 文档范围

本文覆盖迁移管家平台的全部核心功能模块，包括项目空间管理、项目资料索引、数据迁移管理、任务迁移管理、数据校验管理、自定义台账、标签管理及统计看板，共八大模块。同时包含业务流程描述、功能架构图、页面原型设计等内容。

1.3 术语约定

本文使用"平台"指代迁移管家平台，使用"用户"指代平台的使用者（后端管理者、项目管理者、实施工程师、查看者），"项目"指代一个大数据迁移项目。详细术语见第二章。

2术语与概念

为统一沟通语言，以下术语在全文中使用并具有固定含义：

术语定义
大数据迁移 客户大数据业务从源端平台（华为云、阿里云、火山云、自建私有云等）迁移至目标端云平台（腾讯云、AWS、Azure 等）的过程。虽然术语命名为"大数据迁移"，但其实际涵盖公有云和自建私有云等多种源端环境。迁移范围通常包括历史数据与增量数据迁移、调度任务迁移、实时任务迁移等。
旧集群 迁移前客户大数据业务所运行的集群及运行环境，即源端。
新集群 迁移后客户大数据业务将运行的集群及运行环境，即目标端。
迁移空间 平台为每个迁移项目创建的独立工作空间，在空间内管理项目资料索引、数据迁移台账、任务迁移台账等。
迁移场景 按迁移技术路径划分的迁移子项。数据迁移与任务迁移均可创建多个场景，如 hive→hive、holo→starrocks、maxcompute→dlc 等，场景名称由用户自定义。
任务台账 记录所有需迁移的任务清单及其迁移全生命周期状态的结构化数据表，是任务迁移和数据校验的核心载体。
数据校验 通过比对任务输出表在新旧集群的数据是否对齐来判断任务迁移是否成功的过程。输出表数据对齐即视为校验通过。
迁移状态 任务在全生命周期中的状态流转值，详见第四章。
项目管理标签 用于项目管理维度的标记，如按客户规则划分迁移阶段、批次等。
数据校验标签 用于数据校验维度的标记，标识共性排查问题分类。

3业务背景与目标

3.1 业务背景

项目管理者痛点
  • 多个迁移项目并行，无法看到每个项目的具体进展
  • 各项目的过程材料无法收集和沉淀
  • 缺乏统一的项目级进度概览和风险识别手段
  • 项目间经验无法复用，同类问题重复踩坑
现场实施人员痛点
  • 台账维护混乱，各项目格式不统一
  • 项目资料索引维护无规范，查找困难
  • 数据校验排查问题的过程经常丢失
  • 迁移流程未固化，新人学习成本极高

3.2 平台定位

迁移管家平台是一个面向大数据迁移项目的全生命周期管理工具。平台以"项目空间"为管理单元，以"迁移台账"为核心载体，将需求调研、数据迁移、任务迁移、数据校验、客户验收五大阶段流程固化、过程留痕、数据沉淀。

平台服务于三类核心角色：后端管理者（负责项目空间创建与全局管理）、项目管理者（关注全局进展与风险）与迁移实施工程师（关注台账维护与校验排查），同时支持查看者角色用于信息浏览。

3.3 建设目标

目标维度目标描述衡量指标
流程标准化将迁移五大阶段固化为标准流程，每个阶段有明确的输入、输出和状态流转规则流程覆盖率 100%
过程可追溯数据迁移记录、任务改造过程、校验排查过程全量留痕过程记录完整率 ≥ 95%
进度可视化项目管理者可实时查看各项目迁移进度、校验通过率、验收状态看板数据实时刷新
经验可复用沉淀历史项目的迁移台账、排查经验，降低新人学习成本新人上手周期缩短 50%
台账规范化统一台账格式，支持导入导出，减少人工维护成本台账维护效率提升 60%

4业务流程概述

4.1 大数据迁移标准流程

一个完整的公有云大数据迁移项目包含以下五大阶段，平台需要支撑全流程线上化管理：

1
需求调研
旧集群架构、数据流向、数据链路、元数据与数据清单、任务台账、代码清单、数据源清单
→
2
元数据与数据迁移
按清单执行历史数据迁移，完成后标注每个表的数据迁移截止日期
→
3
任务迁移
代码改造 → 迁移至新集群 → 提交调度 → 持续解决报错与优化 → 稳定运行
→
4
数据校验
以任务台账为入口，逐表比对输出数据，每日校验，排查记录留痕
→
5
客户验收
客户对校验通过的表线下验收确认，回填台账补全任务状态

4.2 任务迁移状态流转

任务在全生命周期中的状态定义如下，状态之间按规则流转：

状态定义

状态值类型含义
未开始初始任务尚未启动迁移
改造完成正向任务代码已完成改造，准备提交新集群调度
调度成功正向任务已在新集群成功提交调度并稳定运行
数据校验通过正向任务输出表数据在新旧集群对齐，校验通过
数据校验不通过异常输出表数据未对齐，需排查修复后重跑校验
客户验收通过正向客户线下确认校验结果无误
客户验收不通过异常客户线下确认校验结果有误，需重新排查
挂起挂起因外部原因暂停迁移，后续可恢复
废弃终态任务不再迁移，从清单中标记废弃

状态流转规则

正常路径：未开始 → 改造完成 → 调度成功 → 数据校验通过 → 客户验收通过
校验不通过回退：数据校验不通过 → 排查修复 → 重跑校验 → 数据校验通过（或继续不通过）
验收不通过回退：客户验收不通过 → 重新排查 → 数据校验通过 → 客户验收通过
挂起/废弃：任意正向状态均可转为挂起（可恢复）或废弃（终态）

5系统功能架构

5.1 功能架构图

迁移管家平台采用分层架构设计，从上到下分为用户交互层、业务功能层、基础支撑层三大层次。业务功能层包含八大核心功能模块，覆盖迁移全生命周期管理。

5.2 模块概览

#模块核心职责关键功能
1项目空间管理为每个迁移项目创建独立工作空间，管理成员与权限空间创建、成员邀请、角色权限、项目信息维护
2项目资料索引集中管理项目相关的各类台账与资料链接资料链接维护、分类管理、快速跳转
3数据迁移管理管理数据迁移场景、库表清单及迁移记录迁移场景创建、库表导入、全量/增量迁移状态管理
4任务迁移管理管理任务迁移场景、任务台账及全生命周期状态场景创建、任务导入、状态流转、筛选过滤
5数据校验管理管理数据校验过程、排查记录与客户验收输出表对齐校验、排查记录留痕、验收状态回填

6.1 项目空间管理

功能概述

每个迁移项目启动实施后，后端管理者可以为项目创建独立迁移空间，并将参与项目的成员加入该空间。项目在单独的迁移空间内管理资料索引、数据迁移台账、任务迁移台账等信息，实现项目间数据隔离与权限隔离。

功能需求

F6.1.2成员管理后端管理者和项目管理者可邀请新成员加入空间，指定角色（项目管理者 / 实施工程师 / 查看者），支持移除成员、变更角色。P0

功能概述

项目资料索引模块用于集中维护项目内的各类台账与资料链接，解决实施人员"资料索引维护混乱、查找困难"的痛点。支持编辑和维护项目方案、总体计划、客户导出代码、工作量登记台账等外部链接，同时支持平台内台账的快捷入口。

6.3 数据迁移管理

功能概述

数据迁移管理模块用于管理元数据迁移与数据迁移的全过程。支持创建多个迁移场景，每个场景下导入库表清单，对库表进行批量或逐个的元数据迁移状态、数据迁移状态维护，并记录每次迁移的过程明细。

F6.3.2导入库表清单在每个迁移场景下通过Excel/CSV导入数据迁移的库表清单，包含库名、表名、表类型、数据量（行数）、分区数等基础信息。P0

F6.3.4数据迁移状态管理对每个表维护数据迁移状态，区分全量历史迁移和增量迁移两条迁移线。全量迁移记录状态和迁移截止日期，增量迁移记录状态和最新同步时间点。P0

F6.3.6迁移过程导入支持将每次迁移的过程记录通过Excel批量导入到数据迁移清单中，减少手工录入。P1

6.4 任务迁移管理

功能概述

任务迁移管理是平台的核心模块。支持创建多个迁移场景（如 hive→hive、holo→starrocks、maxcompute→dlc 等），每个场景导入任务基础台账，管理任务从改造、调度、校验到验收的全生命周期状态。支持多维筛选与标签管理。

功能需求

编号功能项功能描述优先级
F6.4.1创建任务迁移场景创建多个迁移场景，如 hive→hive、holo→starrocks、maxcompute→dlc 等，场景名称由用户自定义，每个场景独立管理任务台账。P0
F6.4.2导入任务基础台账通过Excel/CSV导入任务台账，系统自动解析并填充各字段。支持覆盖导入和增量导入两种模式。P0
F6.4.3任务台账列表以表格形式展示任务台账，支持分页、排序、列定制。默认展示任务名称、工作流、迁移状态、调度状态、校验状态等核心字段。P0

6.5 数据校验管理

功能概述

数据校验以任务迁移台账作为入口，所有任务数据校验是否通过取决于任务的输出表数据在新旧集群是否对齐。校验周期内每天对所有表进行校验，通过表匹配到任务，工程师对校验失败的表进行问题排查，排查过程记录到任务台账的备注项中，问题修复后重跑任务并重新校验。

校验流程

功能需求

编号功能项功能描述优先级
F6.5.1校验记录管理每天生成或手动创建校验记录，关联任务台账中的输出表，记录校验日期、校验结果（通过/不通过）、差异详情。P0
F6.5.2排查备注记录在任务台账的备注项中记录排查过程，支持多条历史记录形成时间线。每条记录包含排查时间、排查人、问题描述、原因分析、修复方案。P0
F6.5.3校验状态更新工程师录入校验结果后，系统将任务的数据校验状态同步更新为"校验通过"或"校验不通过"，同时联动更新任务的迁移状态。P0
F6.5.4客户验收回填客户线下验收确认后，实施工程师在台账中回填客户验收状态（通过/不通过），补全任务终态。P0
F6.5.5校验看板按日期维度展示校验通过率、不通过表数量、待排查任务数等指标。P1
F6.5.6共性标签标注在排查过程中发现共性问题时，通过数据校验标签对相关任务进行批量标注（详见6.7标签管理）。P1

6.6 自定义台账管理

功能概述

在任务迁移清单中，工程师可以通过任务的各个属性进行筛选过滤，也可以通过标签进行筛选过滤。筛选出来的数据可以创建单独的台账，台账的基础信息仍然引用原有任务的字段，实现"派生视图"效果。

功能需求

编号功能项功能描述优先级
F6.6.1保存筛选条件用户在任务台账列表中设置筛选条件（属性+标签组合）后，可将当前筛选条件保存为"自定义台账"，填写台账名称和描述。P0
F6.6.2自定义台账列表在迁移场景下展示已创建的自定义台账列表，点击可进入对应台账视图。P0
F6.6.3台账数据引用自定义台账的基础信息引用原有任务的字段，不是数据副本。原任务数据更新时，自定义台账中的数据同步更新。P0
F6.6.4台账独立操作在自定义台账视图中，用户可对筛选出的任务进行状态更新、打标签等操作，操作结果同步回原任务台账。P0
F6.6.5台账编辑与删除支持编辑自定义台账的筛选条件和名称，支持删除自定义台账（仅删除视图，不影响原任务数据）。P1
F6.6.6台账导出支持将自定义台账中的数据导出为Excel。P1
设计要点：自定义台账本质上是"保存的筛选视图 + 引用关联"，不是数据复制。这样设计保证了数据的单一真实来源（Single Source of Truth），避免数据不一致问题。当原任务台账数据变更时，所有自定义台账自动同步。

6.7 标签管理

功能概述

标签管理模块提供两类标签的维护能力：项目管理标签和数据校验标签。标签可批量应用到任务台账上，支持通过标签筛选过滤任务。

项目管理标签

用于项目管理维度的标记，例如：

  • 客户按特定规则拆分迁移阶段（如"第一批次"、"第二批次"）
  • 按业务域分组（如"交易域"、"用户域"、"营销域"）
  • 按优先级标注（如"P0核心任务"、"P1重要任务"）
  • 按实施人员分组
数据校验标签

用于数据校验维度的标记，例如：

  • 共性问题标注（如"时区问题"、"精度丢失"、"NULL值差异"）
  • 排查状态标注（如"待排查"、"已定位"、"待修复"）
  • 问题分类（如"SQL语法不兼容"、"UDF缺失"、"分区格式差异"）
  • 影响范围标注（如"阻塞下游"、"独立问题"）

功能需求

编号功能项功能描述优先级

F6.7.2标签列表展示当前空间下所有标签，按类型分组，显示标签名称、颜色、关联任务数。P0
F6.7.3批量打标签在任务台账中选中多个任务，批量添加或移除项目管理标签/数据校验标签。P0
